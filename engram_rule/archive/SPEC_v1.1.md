# Engram-Rule 神经符号 Transformer 架构指导书

**版本**：v1.1（实测修订版）
**核心思想**：语法规则不以 0/1 位串存储，而以 **Engram 键值记忆 + 深度学习权重** 存储。
**目标**：可微、稀疏、可解释、高速，并在未见词组合上获得统计上站得住的泛化优势。
**证据链**：`engram_rule/DESIGN.md`（静态裁定、审计、修正、实测全过程）；本文件是规范。

---

## 1. 核心裁定（来自静态分析与实现审计）

| 编号 | 张力/歧义 | 裁定 |
|---|---|---|
| 1 | 多哈希 O(1) vs 可微软读 O(N) | 多哈希只取候选槽，软读只在候选集内做 |
| 2 | 哈希键取 token id 还是隐状态 | 哈希键取离散 token id；软读询问取可训练 n-gram 嵌入 |
| 3 | 规则向量如何影响位置 | 规则向量 → 相对位置分桶偏置 `B_k[bucket(i-j)]` |
| 4 | 门控形状不匹配 | `w_k` 为逐维可学向量，`g_k = σ(w_k ⊙ v_k)`，另有标量控制整体强度 |
| 5 | 无触发时是否零计算 | 规则路径与内容路径分开计数；规则路径全空槽时整体跳过 |
| 6 | 规则路径放在 softmax 内还是残差直接加 | 两条路径并存：打分路径给位置偏好，直接路径保证冲突加权可解释 |

## 2. 总体架构

```text
输入 token 序列
    ↓
嵌入查表 + RoPE 位置编码
    ↓
┌─────────────────────────────────────┐
│         Engram-Rule 注意力块         │
│  Engram 查找：n-gram 哈希 → 规则向量 v │
│  规则驱动注意力：α_ij = softmax(...)   │
│  内容门控 gc = σ(W·h)               │
│  混合聚合：规则路径 + 内容路径         │
│  残差相加：h = h + Attn             │
│  前馈网络                           │
└─────────────────────────────────────┘
    ↓  重复 N 层  ↓
输出层：任务头
```

## 3. 模块详解

### 3.1 输入与 RoPE
- 分词：BPE / WordPiece / SentencePiece。嵌入矩阵可训练。
- RoPE 提供相对位置，规则向量可依赖相对距离分桶。

### 3.2 Engram 记忆
- 可微键值记忆 `{ (k_i, v_i) }`；键 = 上下文 n-gram 的多哈希；值 = 连续规则向量。
- 查询：每位置取 n-gram，多哈希查表得候选规则向量。
- **可微软读只在候选集内做**，避免 O(N) 全表求和。

### 3.3 规则驱动注意力
α_ij = softmax( Σ_{k∈触发} w_k·f(v_k,i,j) + λ·g_c·(q_iᵀk_j)/√d_k )
- `f(v_k,i,j)`：规则向量 → 相对位置分桶偏置。
- `g_c`：内容门控，可学到"规则一触发就关内容"。

### 3.4 冲突加权与门控
h_{l+1} = h_l + Σ_{k∈触发} g_k·v_k， g_k = σ(w_k ⊙ v_k)

### 3.5 尺度归一化（实测发现）
规则分曾被内容分淹没 47 倍 ⇒ "规则路径没用"的假象。修法：
bias_n = (bias − mean)/(std + ε)；rule_score = bias_n · rule_scale（可学，初值 2.0）。
剖面形状不变，可解释性不受影响。

### 3.6 残差与条件计算
- 无规则触发时 `h_{l+1} = h_l`，零计算；规则路径全空槽时整体跳过。
- 内容路径由门控 `g_c` 决定是否关闭。

### 3.7 前馈网络与输出层
- 标准 FFN 正常梯度更新；输出层按任务：LM softmax / 分类 / 序列标注。

## 4. 训练流程

### 4.1 前向
```python
for layer in layers:
    h = rope(h)
    ngrams = extract_ngrams(h)          # 离散 token id
    rule_vecs = engram_lookup(ngrams)   # 多哈希，候选集内软读
    attn = rule_attention(rule_vecs, h)
    h = h + attn
    h = ffn(h)
```

### 4.2 反向
- 损失：交叉熵；更新 Engram 值/规则权重/注意力/FFN 权重。
- 稀疏更新：只有被检索到的槽位收到梯度。
- 不可导触发：直通估计器或 Gumbel-Softmax 松弛。

### 4.3 检查套件与纪律
- `checks.py` 13/13；`checks_eval.py` 9/9。
- 关键检查：H2（重叠必须**全量**查，不能只查前 400 行）、C9（内容门压到 2e-9 与 λ=0 逐位相同）、
  C10（全空槽时 ngram_query 调用 0 次）。
- **纪律：写完代码先检查，通过检查再跑对比。**

## 5. 实测结论（可靠语料，3 种子）

| 指标 | A: ER | A: 稠密(同结构) | A: 稠密(匹配参数 15.9M) |
|---|---|---|---|
| ppl | 2.0518 | 2.0454 | 2.4027 |
| acc | 0.6827 | 0.6829 | 0.6383 |
| 未见词组合 | **5.419 / 0.5293** | 8.273 / 0.4910 | — |
| tokens/s 比值 | 0.25–0.34× | — | — |

中文语料同向：ER 1.7984 vs 1.8027 vs 匹配参数 1.8429；速度 0.24–0.31×。

结论：① 分布内质量打平（差异小于种子极差）；② 同参数预算下 ER 更有效率；
③ **未见词组合泛化显著更好（ppl 低 35%）**；④ 速度恒慢 3–4 倍，L=16→256 无交叉点。

## 6. 已知瓶颈

| 瓶颈 | 原因 | 状态 |
|---|---|---|
| 速度慢 3–4 倍 | 规则路径加在内容路径之上，不是替换；内容路径仍全量稠密 | 未解决 |
| 长序列更差 | `bias.gather` 物化 (B,L,L) 相对位置矩阵，L=4096 时显存压力大 | 未解决 |
| 跳过只省小头 | 跳过只覆盖 bucket_proj，哈希/n-gram 查询/软读仍全量跑 | 未解决 |
| 中文语料重叠 21 行 | zh_corpus 连续文本切片，模板重复导致重行；H2 未验中文 | 未修 |
| 未见词组合仅 seed 0 | 不是 3 种子均值 | 未补 |

> **编者注（对齐实测记录，见 DESIGN.md §8-C）**：上表第二条"O(L²) gather"的说法要修正——
> gather 的输出与它要相加的稠密注意力**同为 (B,L,L)**，不是**额外的**渐近项；
> L=4096 变慢是整体显存压力（多个 (B,H,L,L) 张量）所致。带状化仍是正确的工程方向，
> 但理由是省显存与常数，不是改渐近阶。

> **编者注 2**：第六节"跳过只省小头"一项的**部分**已在 §8 修正中处理（Fix B：软读只算
> 有存活候选的位置，C10 验证全空槽时 ngram_query 0 次调用）；
> 但哈希（slot_ids）仍对所有位置全量跑，所以"整条路径的跳过"仍未完成——表里的状态对，成因要更正。

## 7. 下一步工程路线

1. **内容路径真替换**——让规则触发时内容路径可被门控为真 0，而非叠加。
2. **规则路径带状/索引化**——去掉 (B,L,L) 物化，改带状或稀疏索引写法。
3. **跳过覆盖整条规则路径**——跳过要包含哈希、n-gram 查询、软读，而非只跳 bucket_proj。
4. **中文语料泄漏修复**——`zh_corpus` 改句子级采样，保证训练/测试逐行不相交；H2 全量验中文。
5. **未见词组合补 3 种子均值**。
6. **硬件混合**——CPU 做哈希和查表，GPU 做注意力聚合。

## 8. 验收标准

| 指标 | 目标 |
|---|---|
| 困惑度 | 分布内不差于稠密，未见词组合显著更好 |
| 准确率 | 同上 |
| 推理速度 | 规则稀疏时快于稠密 |

| 加速比 | 稠密 FLOPs / 实际 FLOPs |

| 泛化 | 留出 n-gram 上的表现 |

## 9. 结论

Engram-Rule 已表现出：分布内质量打平；同参数预算下优于稠密基线；
**未见词组合泛化显著更好**；可解释、稀疏触发、残差捷径。
但速度仍是硬伤。下一阶段的重点不是再改理论，而是：

> **把内容路径真正稀疏掉，把规则路径带状化，把跳过覆盖整条规则路径。**
