# 中文语义组合实验 v0：手写字词语义 + 反馈学习（非 transformer）

**日期**：2026-10-22
**分支**：`exp-arch-1`
**目标**：验证一条非 transformer 路线的可行性——人（本 agent）手写字/词的**形式化语义**，
模型用**显式语法组合**得到句义，再由**对错反馈**学习自己不会的那部分（语义选择限制），
最后用一个**验证器**做最小 RSI 闭环。

> 本文件先写设计与可证伪预测，再写代码。所有结论必须来自脚本落盘的读数。

---

## 一、为什么不是 transformer

本实验的"理解"是一个**离散结构**，不是向量序列：

```
句子 ──分词──▶ 词条（语义类 + 论元框架） ──组合规则──▶ 句义帧（roles / mods）
                                                        │
                                              打分器（离散权重表）
                                                        │
                                                 接受 / 拒绝 + 角色槽
```

- 没有注意力、没有矩阵乘、没有梯度下降；打分器是**特征计数表**（感知机式整数权重）。
- 组合规则是显式文法（主谓、动宾、把/被、状中、定中、在字结构），人可以逐条审阅。
- 这是"可解释"的硬约束：每一个句义都能回溯到"哪条规则 + 哪个词条"。

**这不是要证明它比 transformer 强**——本实验只测一件事：
手写的语义类 + 稀疏反馈，能否让模型在**没见过的词组合**上判断句义是否成立。

## 二、formalism（形式化表示）

### 2.1 词条（手写）

| 字段 | 例 | 说明 |
|---|---|---|
| `pos` | V / N / PRON / A / ADV / P / PART | 词性 |
| `cls` | `FOOD` / `ANIMAL` / `PLACE` … | 语义类（实词） |
| `frame` | `[AGENT, PATIENT]` | 动词的**有序论元框架**（第一项是主语角色） |
| `opt` | `[PATIENT]` | 可省略的论元 |

语义类带**属性向量**（人写死）：`animate / edible / liquid / place`。
属性是模型可观测的**特征**，但"哪个动词的哪个角色允许什么属性"**不写进词典**——
那正是模型要从反馈里学的东西。

### 2.2 句义帧（输出）

```python
{"kind": "event"|"state"|"entity",
 "pred": "吃",
 "roles": {"AGENT": "我", "PATIENT": "饭"},
 "mods":  {"NEG": True, "PERF": True, "DEGREE": True, "ATTR": "红",
           "LOC": "家", "TIME": True, "BA": True, "BEI": True},
 "construction": "SVO"|"BA"|"BEI"|"adj_state"|"loc_state"|"entity"}
```

`canon()` 给出忽略 `construction` 的规范形式，用于对拍。

### 2.3 组合规则（显式，8 类）

| 编号 | 规则 | 语义动作 |
|---|---|---|
| R1 | `NP + V(+NP)` | 主语填 `frame[0]`；动词后第一个 NP 填第一个未占宾语槽 |
| R2 | `NP + AP` | `state(adj, THEME=NP, DEGREE)` |
| R3 | `NP + 在 + NP` | `state(在, THEME=NP1, LOC=NP2)` |
| R4 | `在 + NP + VP` | VP 加 `LOC` 修饰 |
| R5 | `不/今天 + VP` | VP 加 `NEG` / `TIME` |
| R6 | `很 + AP` | AP 加 `DEGREE` |
| R7 | `NP + 把 + NP + VP` | `AGENT=NP1, PATIENT=NP2, BA` |
| R8 | `NP + 被 + NP + VP` | `PATIENT=NP1, AGENT=NP2, BEI` |
| R9 | `A + 的 + N` | `entity(N, ATTR=A)` |
| R10 | `V + 了` / `VP + 了` | 加 `PERF` |

规则本身**不学习**；学习只发生在打分器（见 §三）。

## 三、学习信号：反馈

训练样本 = `(句子, 正确句义 或 REJECT)`。

- **正例**：句义成立，给出完整 roles/mods。
- **负例**：句义不成立（语义选择限制被违反），标 `REJECT`。

打分器对每个候选句义打分，并与"拒绝假设"比较；预测错误则做感知机更新：

```
正确 > 预测： w[正确特征] += 1, w[预测特征] -= 1
```

特征集（全部离散）：

```
bias, construction, verb, verb_role,
verb_role_class, role_class,
verb_role_anim, role_anim,
verb_role_edible, role_edible,
verb_role_liquid, role_liquid,
verb_role_place, role_place
```

关键：`role_anim` / `role_edible` / … 是**跨动词共享**的特征。
只在"吃/喝/看…"上见过"无生命主语不行"，应能迁移到没见过的动词组合。

## 四、RSI 闭环（最小版）

1. 用**验证器**（手写的角色—属性约束表，等价于"我逐句给反馈"）给未标注句子打伪标签；
2. 伪标签加入训练集，重训打分器；
3. 在固定 held-out 上评测，重复 3 轮。

**诚实边界**：验证器就是手写语义的属性约束，模型的上限 = 验证器。
所以 RSI 只能证明"从少量人工反馈扩展到大覆盖"这件事有效，**不能**证明模型超过人。
如果 RSI 没有提升，如实报"无提升"。

## 五、可证伪预测与对照

| 编号 | 预测 | 判据 |
|---|---|---|
| **P1** | 正例 held-out 的句义精确匹配 ≥ 80% | `evaluate.py` 的 `valid_exact` |
| **P2** | 负例 held-out 拒绝率 ≥ 80% | `invalid_reject` |
| **P3** | 打乱语义类后，负例拒绝率**显著下降**（≥ 20 个百分点） | `random_class` 对照 |
| **P4** | 只用位置特征（不看词义）时，负例拒绝率接近随机 | `position_only` 对照 |
| **P5** | RSI 三轮内 held-out 总体准确率不下降 | `rsi.py` 每轮读数 |

**对照的意义**：P3/P4 是可失败性证明——如果打乱语义类后指标不降，
说明"语义先验"根本没起作用，P1/P2 的数字只是语法位置带来的假象。

**已知局限（写死，不许事后改口）**：

- 种子规模：45 词条、约 50 训练句；**不是"全部汉字"**。
- 字级（3500/8105 字）扩展、词级 6.9 万条扩展**未做**；本实验只验证机制。
- 语义表示是浅层帧，不处理时态、量化、指代、隐喻、语篇。
- 单 seed；没有种子极差（本项目明令禁止跑 3 seed）。
- 验证器 = 人写规则，不是独立真值；RSI 的天花板由它决定。

### 6.3 撤回与边界（新增）

1. **撤回 v0 的 P3 判据**。v0 的 `random_class` 只换类名、不重算 gold，
   测到的是"27/59 训练标签与新词典矛盾"，不是"语义先验有用"。
   v0.1 改为自洽世界（重算 gold）：负例拒绝 1.00→1.00（稳定），
   总体 −12.9pp 来自标签分布改变（训练正例 38→19），不能归因于语义。
2. **撤回"0.9355 是语义泛化"的措辞**。v0 的 held-out 每句只有 1 个候选，
   exact match 等价于接受率。v0.1 的 1.0000 同样受此限制：**没有歧义句**，
   15 条组合规则的选择从未被真正考核（`canon` 还忽略 construction）。
3. **撤回"跨动词迁移成立"**：LOVO 显示 `吃/喝/去/喜欢` 在 0.50–0.67。
4. 仍未解决：多义词、OOV（分词遇到词表外直接抛错）、量词/时态/指代/语篇、
   字级→词级的扩展路径（见 `EXPERT_REVIEW.md` §二、§四）。

## 七、v0.2：词义歧义（2026-10-22）

专家共识的第一优先级是"让 exact match 真正考核组合/词义选择"。
v0.2 用**一词多义**实现：`看` 有两个义项，句法框架相同、选择限制不同。

### 7.1 改动

| 项 | 内容 |
|---|---|
| 词条 | `ENTRIES[form]` 改为**义项列表**；`看` = `看/read`（PATIENT 必须可读）+ `看/visit`（PATIENT 必须是地点） |
| 解析 | 每个义项生成候选；`看` 句有 **2 个候选**，exact match 必须选对义项 |
| 验证器 | 支持 `{"cls": "READABLE"}` 这类词类约束 |
| 训练 | 负例惩罚**所有**当前被接受的候选（不只最优），否则另一个义项漏学；门禁加入类否决 |
| 数据 | 66 训练句 / 57 held-out（31 正 / 26 负） |

### 7.2 读数

| 口径 | 正例 | 负例 | 总体 |

| **v0.2 主模型** | **31/31** | **26/26** | **1.0000** |
| always-accept | 31/31 | 0/26 | 0.5439 |
| always-reject | 0/31 | 26/26 | 0.4561 |
| cell 查表 | 28/31 | 11/26 | 0.6842 |
| verifier（上限） | 31/31 | 26/26 | 1.0000 |

对照：自洽随机世界 0.8421（负例 1.00 稳定，正例下降来自训练正例 43→23）；
旧 gold 的标签矛盾对照 0.7544；position-only 0.5088（≈ always-accept）。
`看` 的 held-out 义项选择：`妈妈看书/他看书` → read，`小明看学校/狗看学校` → visit，4/4 正确。

### 7.4 RSI（200 条冻结评测集，验证器标签）

| 组 | 第 1 轮 | 第 2 轮 | 第 3 轮 |
|---|---:|---:|---:|
| A 验证器标签 | 0.995 | 0.995 | **0.980** |
| B 打乱接受/拒绝 | 0.775 | 0.705 | 0.660 |
| C 不 RSI | — | — | 0.950 |

A−B = +32.0pp，McNemar p<0.0001（A 独对 66、B 独对 2）。
**但 A 第三轮从 0.995 掉到 0.980** ⇒ 加更多伪标签**不是单调自我改进**。
签名重叠 68/112 ⇒ 不能叫未见组合的泛化；验证器仍是上限。

### 7.5 边界（新增）

1. 只有 `看` 有真歧义；其余句子仍单候选，exact match 仍主要是接受率。
2. 100% 是 45 词闭集上的读数；LOVO 的 0.33–1.00 才是真实边界。
3. `看/visit` 的"参观"义与 `看/read` 的"读"义是两类选择限制；
   第三义"看/look"（任何宾语）不在词典里，所以"看石头"被拒是**词典覆盖**问题，
   不是模型判断正确。这一点必须和"理解了语义"分开说。
4. RSI 第三轮退化，说明伪标签的边际收益会转负；需要按验证器置信度筛选，
   而不是固定每轮 60 条。

## 八、v0.2.1：把 RSI 改成主动学习（2026-10-22）

### 8.1 动机

v0.2 的 A 组（每轮固定加 60 条验证器标签）第三轮从 0.995 掉到 0.980——
伪标签的边际收益转负。改成只挑模型**当前判错**的句子，再向验证器要标签。

### 8.2 读数（200 条冻结验证器评测集）

| 组 | R1 | R2 | R3 | 累计新增标签 |
|---|---:|---:|---:|---:|
| A_random（固定每轮 60） | 0.995 | 0.995 | **0.980** | 180 |
| **A_active（只挑错误）** | 0.995 | **1.000** | 0.995 | **4** |
| B（打乱接受/拒绝） | 0.775 | 0.705 | 0.660 | 180 |
| C（不 RSI） | — | — | 0.950 | 0 |
| **D（纯自训练，模型自己打标签）** | 0.950 | 0.950 | **0.945** | 180 |

McNemar：A_active − D = **+5.0pp，p=0.002**；A_active − B = +33.5pp，p<0.0001。

### 8.3 结论（写死，不许事后美化）

1. **纯自训练没有提升，反而略降**（0.950 → 0.945）。没有外部验证器的
   "RSI 自行学习"在本设置下**不成立**。
2. **增益来自"向验证器有针对性地提问"**：4 条标签到 1.000，180 条随机标签到 0.980。
   这应改名为 **active verifier querying + discrete learner**，不是 RSI。
3. 验证器 = 手写的角色—属性约束，模型上限 = 验证器。这条读数只能叫
   "与老师一致率"，不能叫"理解"。
4. 签名重叠 68/112：评测句子与新增标签共享大量 (verb, role, class) 单元，
   所以连"未见组合泛化"也不能声称。

### 8.4 对"理解语言"的含义

当前系统证明的是：**离散组合 + 手写语义 + 少量针对性反馈**可以在闭集上
做到与手写语义规则一致，并且比 always-accept（0.544）、cell 查表（0.684）
和纯位置特征（0.509）显著更好。

它没有证明：开放词表、未见句法结构、语篇、指代、量化、时态。
下一步必须先补**结构覆盖**（被字句 held-out 目前为 0 条；把/被/的/了之外的
构式未实现），再谈扩词典；否则 100% 只是 45 词闭集内的插值。

## 十二、v0.4：开放词表 + 词典增长 + 独立人工 held-out（2026-10-22）

### 12.1 人工集抓到的两个真缺陷（已修）

1. **共享角色回退过宽**：把「聪明」的 THEME 约束回退成**所有形容词共享**的 role 约束，
   导致「教室很干净 / 电脑很新 / 茶很热」全被误拒。
   修正：只有语义上普遍的角色（AGENT/EXPERIENCER/POSSESSOR/RECIPIENT/GOAL）允许共享回退；
   PATIENT/STIMULUS/THEME/LOC 必须逐谓词证据。
2. **负例信用分配错误**：原先负例惩罚整句所有槽位，于是「老师在苹果」把
   `THEME=老师` 也学成负证据，误伤「老师在家」。
   修正：反馈改为**带原因的**——验证器给出违规角色，只惩罚该角色。

### 12.2 开放词表（OOV 降级）

`tokenize(sent, strict=True|False)`：

| 模式 | 行为 |
|---|---|
| `strict=True` | 词表外直接 raise（训练/检查口径不变） |
| `strict=False` | 连续未知字符合并成一个未知词（`\x00` 前缀），作为**无属性 NP** 参与组合，不抛错 |

- 新规则 R22/R23：`S + 的 + N -> 关系化 NP`。
  缺口 = S 中**未填且允许省略的宾语角色**；中心名词补进该缺口，
  句义写成带嵌套事件的实体：
  `entity("书", comps={"REL": 说(AGENT=他, PATIENT=书)}, REL_ROLE="PATIENT")`。
- `canon` 修正：嵌套 `comps` 改为**递归调用 canon**，不再原样 `_freeze`。
  原来会把补语的 `construction`（解析器 "SVO" vs gold "event"）也算进比较，
  导致两条看起来完全一样的句义判不相等。
- 解析失败预期集合新增 `我跑的猫`（跑没有可选宾语 ⇒ 没有关系化缺口 ⇒ 无解析）。

### 15.2 读数

| 口径 | 结果 |
|---|---|
| 主 held-out（82 条） | **47/47 正、35/35 负 = 1.0000** |
| 独立人工 held-out（81 条：57 正 / 24 负） | **1.0000**（模型与验证器均 1.0000） |
| `他说的书` | 计入准确率，**正确**（REL 嵌套事件） |
| **覆盖缺口** | **0 条** |
| 300 条冻结大 held-out | 0.9800（正 0.9928 / 负 0.9691） |

### 15.3 边界

1. 只支持**宾语关系化**且缺口必须是"可省略宾语"；主语关系化
   （"说话的人"）与其他缺口类型未实现。
2. **关系化 NP 作为独立短语时语义完整；一旦嵌入更大句子，
   角色槽只存词头字符串，REL 会丢失**（`我看他说的书` 目前会退化成
   `看(我, 书)`）。这是下一步要修的表示缺口。
3. 关系从句的主语不能是缺口（"他说的书"里"他"是施事，书是受事）；
   "书说的他"这类不合语义的组合不会被额外过滤。

## 十七、v0.7：ATTR/QUANT 嵌套 + 主语关系化（2026-10-22）

### 17.1 改动

- `_np_value`：带 `ATTR` / `QUANT` / `comps` 的 NP **一律存整个实体**；
  光杆 NP 仍存词头字符串。量化/定语作宾语、主语时不再丢修饰。
  更新了 6 处量化 gold（一个苹果 / 一本书 / 一只猫 / 一只狗）。

  新增词条 `人`、`说话`。

## 十八、v0.8：跨句指代 + 对话状态（2026-10-22）

### 18.1 规则（规则式，不是学习）

| 代词 | 绑定条件 |
|---|---|
| 他 | 最近一个 `cls == HUMAN` 的提及 |
| 它 | 最近一个 `cls != HUMAN` 的提及 |

- "最近" = 语境提及列表里**从后往前**第一个匹配项。
- 先行词还必须满足**谓词对该角色的选择限制**（`ROLE_REQ`），否则视为无先行词。
  例：`猫和鱼喝水。它很聪明。`——`聪明` 的 THEME 必须有生，
  所以绑定 `鱼`，不是字面上更近的 `水`。
- 语境提及按 **token 词序**收集（不是句义 roles 的插入顺序）；
  代词就地解析，跨句累积。
- 无匹配先行词 ⇒ 绑定失败 ⇒ **该句必须拒绝**。

### 18.2 读数（手写 gold，15 正 + 5 无先行词 + 2 不兼容）

| 指标 | 值 |
|---|---:|
| 最近匹配绑定准确率 | **1.0000（15/15）** |
| "绑定第一个匹配"对照 | **0.5333（8/15）** |
| 无先行词拒绝（确认绑定失败） | **1.0000（5/5）** |
| 不兼容先行词拒绝（确认绑定失败） | **1.0000（2/2）** |

句内指标不变：主 held-out 82 条 1.0000；人工 held-out 85 条 1.0000；
300 条冻结大 held-out 0.9767（正 0.9924 / 负 0.9643）。
`first-match` 对照只有 8/15 ⇒ "最近"规则确实在起作用，不是恒真。

### 18.3 边界

1. 只有 `他` / `它`；没有 `她` / `他们` / `它们`，不处理性与数。
2. 规则式绑定，不是学习；选择限制来自手写 `ROLE_REQ`。
3. 只处理"前文有提及 + 当前谓词选择限制"的情形；
   不处理事件指代（"这样做"）、零代词、桥接指代。
4. 语境是累积的提及列表；没有话题结构、没有话语关系、没有指代链的消解。
5. 若没有任何先行词满足选择限制，句子被拒绝——人可能会用常识补出指代。

## 十九、v0.9：时态/体标记（2026-10-22）

### 19.1 表示

体标记作为事件帧上的显式 `mods`：

| 标记 | 特征 | 位置 |
|---|---|---|
| 了 | `PERF=True` | 动词/VP 后 |
| 过 | `EXP=True` | 动词/VP 后 |
| 着 | `PROG=True` | 动词/VP 后 |
| 正在 | `PROG=True` | 动词前（状语） |

### 19.2 组合规则（`_add_aspect`）

| 组合 | 判定 |
|---|---|
| `{了}` / `{过}` / `{着}` / `{正在}` | 接受 |
| `{过, 了}`（"吃过饭了"） | 接受 |
| 重复标记（"了了"） | **拒绝** |
| `{了, 过}`（"吃了过"，顺序反了） | **拒绝** |
| `{着, 过}`（"吃着过"） | **拒绝** |
| `{着, 了}`（"吃着饭了"） | **拒绝**（模型约定） |
| 状态动词 + 着/正在（"喜欢着"/"正在喜欢"） | **拒绝** |
| 体标记没有谓词（"我正在"/"我饭了"） | **拒绝**（无句法解析） |

状态动词：`喜欢/爱/知道/认识` 标记 `stative=True`；`有` 未标记
（"有着悠久的历史"合法，但当前模型不建这个用法）。

### 19.3 读数

| 口径 | 结果 |
|---|---|
| 主 held-out（82 条） | **47/47 正、35/35 负 = 1.0000** |
| 独立人工 held-out（96 条：66 正 / 30 负） | **1.0000**（模型与验证器均 1.0000） |
| 训练集 | 114/114 |
| 300 条冻结大 held-out | 0.9767（正 0.9924 / 负 0.9643） |
| 体标记冲突句 | 9 条全部 **0 候选**（进入 C3 预期解析失败集合） |

### 19.4 边界

1. `正在 + 了`（"正在吃饭了"）被当前规则**拒绝**；真实汉语在部分语境可接受。
   这是刻意的简化，不能当作"模型判断正确"。
2. 只实现 `了/过/着/正在`；没有 `呢/来着/起来/下去` 等。
3. 体标记由规则赋值，**不是学习**；学习只发生在选择限制的打分器。
4. 状态动词表是手写的、粗粒度的；没有更细的 aktionsart（瞬间/持续/终结）。
5. 只有**体**，没有**时**——没有相对说话时间的过去/现在/将来锚定。
6. 体标记不参与打分器特征；exact match 检查它们，但模型不会"学会"用体标记消歧。

### 19.5 复现

```bash

python checks.py && python train.py && python evaluate.py
python manual_eval.py && python large_eval.py
```
