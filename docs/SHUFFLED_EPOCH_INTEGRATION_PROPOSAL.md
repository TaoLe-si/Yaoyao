# Experimental shuffled epoch cursor (not integrated)

New sources: shuffled_epoch_cursor.hpp and test_shuffled_epoch_cursor.cpp. C++17 CPU-only; no training, controller, CUDA, or production modification. Compile/run remains for the parent. This agent's bash/pwd and ripgrep-backed discovery could not launch, so no build result is claimed.

## Inspected behavior

pilot_slot_cursor.hpp defines PilotCursor with canonical docs, slots {doc,target}, and next. Work.doc indexes docs directly. take advances target before compute and allocates increasing document indices. Active slots can remain unfinished when next == docs.size(). bpe_pilot_reader.hpp preserves per-token loss masks; PilotCursor legacy mode strips terminal EOS once, BPE mode does not. This helper copies the already-normalized cursor; it never strips a second EOS or reorders token storage.

## Native checkpoint compatibility (inspected)

slot_resume_snapshot.cuh captures weights, Adam moments/variance, per-slot recurrent s/mem tensors, cursor, next, steps, and requires an optimizer boundary (no active slot/tape/pending gradient). restore reinstates tensors and cursor then projects/zeros gradients. slot_checkpoint_file.cuh SCP1 has no epoch/permutation; its identity includes model manifest, tokenizer, data SHA256, budget and optimizer/projection label, with trainer-specific schedule suffix. File checksum is bundle_hash, not a substitute for sidecar cryptographic binding.

**Existing load_slot_file rejects c.doc >= next. This is invalid for canonical shuffled document IDs!** Do NOT use the old loader on shuffled SCP1 snapshots, relax production validation, fake next=N, or reorder docs on mid-epoch restore. Build a NEW experiment-only loader/schema that validates rank[doc] < next against the verified permutation, retains every original shape/finite/variance/checksum/identity check, rejects duplicate active docs, and binds the scheduler sidecar to the exact tensor checkpoint. The original loader remains appropriate for initial legacy checkpoint1200 adoption only. Existing capture takes a nonconst PilotCursor reference; an experimental adapter should snapshot the helper's const cursor via a copy or a new const-compatible capture, not expose mutable scheduling internals. Full tensor checkpoint resume is therefore NOT implemented by this CPU helper.

Parent-confirmed deployment identity is checkpoint_identity(...) plus arch2-controlled-v1-external-lr (preserve exact source bytes/newlines when integrating). Parent validated the 116-step epoch restart and confirms checkpoint1200 is mid-epoch. Do not infer exhaustion solely from arithmetic or the step number; use the restored all-slot cursor state. ## Safe route

1. In a NEW experimental trainer only, load the identical checkpoint1200 model, optimizer, scheduler, all recurrent slot states, and PilotCursor snapshot for each arm. Verify existing checkpoint/corpus/tokenizer identities first. Do not replace/reset this snapshot. Construct ShuffledEpochCursor from that loaded cursor and explicit shared seed plus verified corpus/tokenizer/preprocessing identity. Initial order is identity, epoch counter is local zero (not an assertion that production was in epoch zero).
2. Finish the inherited current epoch in original order for BOTH arms. begin_next_epoch refuses until next == document count AND every assigned slot target reached its document end. Exhaustion is a scheduling property; caller MUST additionally ensure every issued Work completed its update successfully and no GPU work is in flight.
3. At that common true boundary, call begin_next_epoch(false) for baselinefixedorder, true for shuffle. All slots become unassigned; following Work.reset resets recurrent state for each newly assigned document. Work.doc always remains the canonical document index, never the permutation position. Never pass helper next back into ordinary PilotCursor.take: its semantics now differ.
4. For resume, write save(checkpoint_digest) sidecar containing format version, verified dataset identity, exact checkpoint identity, explicit seed, epoch, mode, whole permutation, next allocation position, all slot doc/targets. At a committed barrier persist checkpoint and sidecar to unique files and publish an atomic manifest referencing hashes of BOTH. Verify those hashes, corpus/tokenizer/preprocessing identity, slot count, and seed BEFORE restore. Never treat a step number or path as checkpoint identity. Caller computes/verifies cryptographic hashes; this helper does not hash artifacts itself.
5. Restore using canonical normalized docs (not permuted docs), then sidecar scheduling state; restore recurrent slot tensors from the exact bound checkpoint with the same slot indexing. If native checkpoint also stores cursor fields, require exact equality with the sidecar slot doc/target/next before accepting. Helper restore currently treats sidecar as authoritative and does not itself cross-check native cursor fields. Never silently fall back to identity order if an experiment sidecar is missing or mismatched. New experiment checkpoints require sidecars. Legacy initial checkpoint1200 alone is an explicit one-time adoption path, not a generic fallback.
6. Distinct future file prefixes: plateau_pair_baselinefixedorder_1200_* and plateau_pair_shuffle_1200_*. Prefer equal FULL post-boundary epoch budgets to equal update counts: order changes slot packing and therefore steps per epoch. Match validation set/order, optimizer, seed, settings, and stop gates. Report optimizer updates, target positions, supervised targets, document exposures, and wall time for each arm; equal epochs control data exposure, not update count, and that residual confound must be explicit. Predeclare schedule behavior when steps differ. Log inherited-epoch completion step and shuffled exposure. A short experiment ending before exhaustion has zero shuffle exposure and cannot judge this intervention. An alternative immediate reset would require a separately documented identical cursor AND recurrent-state reset for both arms; it is deliberately not implemented.

## Guarantees and limits

The helper uses versioned SplitMix64 plus rejection-sampled Fisher-Yates; explicit permutation serialization avoids library RNG/shuffle variation. Documents are allocated once per epoch, and tokens/masks never move or change. CPU tests cover each next-token pair exactly once, reset once per doc, legacy mid-epoch adoption, several epochs, save/resume at many interruption points, wrong seed/identity/checkpoint, truncation/trailing data, duplicate order, and premature epoch transition. Tests use synthetic BPE-shaped data, not the production corpus. They compare CPU scheduling work, not training numerics.

Like PilotCursor, take advances before compute. Snapshot only after successfully committed work, or keep a pre-step helper copy and roll it back alongside ALL training state on failure. The helper cannot infer pending asynchronous work, validate recurrent tensors, provide atomic checkpoint persistence, cryptographically verify identity strings, or prove actual checkpoint1200 continuity until the parent wires/validates the native checkpoint integration. No live experiment is started by these files.
