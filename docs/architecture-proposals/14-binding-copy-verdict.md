# 14 · 2 层泛化的决定性诊断：数据规模治好了「退化重复」，治不好「绑定与复制」

> 本文修正 doc 12 的判定。doc 12 用 probe3（361 篇绑定样本）把交叉注入绑定率从 0/18 拉到 10/18，
> 据此判定「**数据问题，不是架构问题**」。本轮在固化的 2 层架构上做了三组实验，
> **结论是分层的**：doc 12 对「流畅性」的判断成立，对「绑定/复制」的判断被混淆了——
> 它的 18 个测试名字**全部来自一个 30 词的封闭名字集**，所以测到的是**记忆**，不是组合泛化。
>
> 所有数字均为【实测】。架构：2 层槽位，解码 ~8.5k tps（满头）/ 8 线程。

---

## 一、结论摘要

| 能力 | 小数据（L2，2 133 篇） | 大数据（L4，18 038 篇，8.3×） | 判定 |
|---|---|---|---|
| **退化性重复** | 4/12 出现（`小树树树树…`） | **0/12** | ✅ **数据治好了** |
| 输出流畅性 | 塌缩成模板 | `好的，我记住了。` | ✅ **数据治好了** |
| **新名字绑定** | 0/12 | 1/12 | ❌ **数据没治好** |
| **新配对绑定**（名字见过+颜色见过+组合未见） | — | **0/12** | ❌ **数据没治好** |
| **复制（原样）** | 0/15 | 0/15 | ❌ **数据没治好** |
| **复制（列表）** | 0/4 | 0/4 | ❌ **数据没治好** |

**决定性实验（纯复制语料，NLL 0.11）**：3 500 篇语料**全部是复制任务**，训到训练 NLL **0.11**
（与 L2 的 0.09 同档 = 完全记住），仍然：

| | 结果 |
|---|---|
| 语料内句子复制 | **13/18**（且带口吃：`小小小王在看书。`） |
| **语料外句子复制** | **0/5** |
| 列表复制 | 1/3 |

**⇒ 即使把全部训练预算给复制任务、并把语料背到 NLL 0.11，模型仍不能复制未见过的内容。**
这是**架构限制**，不是数据限制。

## 二、决定性实验 1：纯复制消融

语料 `data/noffn_copy/conversations.txt`：**3 500 篇 / 99 309 token / 32 307 监督位置**，
**100% 是复制任务**（2 600 篇原样复制 + 900 篇列表复制）。句子取自 26 主语 × 15 谓语 = 390 句
+ 10 独立句，列表从 42 个词条随机组合。

训练 207 步，训练 NLL **0.11**。

```
语料内 "小王在看书。"      -> "小小小王在看书。"          ✅ 内容在（带口吃）
语料内 "小张在写字。"      -> "小小王在写字。"            ✅
语料外 "小张在打球。"      -> "小小小小小小张在在钓鱼。"   ❌ 换成了语料内的谓语
语料外 "老师在备课。"      -> "小小吴在在写字。"          ❌
语料外 "爷爷在下棋。"      -> "爷爷爷�爷在下棋。"         ✅ 偶然
列表   "红色、猫、桌子"    -> "红色、猫、桌子"            ✅ 完全正确
列表   "蓝色、狗、椅子、北京" -> "蓝色、蓝色、狗、蓝色、桃子" ❌
列表   "绿色、鱼、书包、尺子、上海" -> "绿色、绿色、鱼、绿色、书包" ❌
```

**读法**：模型能复现**背过的整串**（含 3 项列表），但一旦内容未见过就退化成
「语料内的词 + 口吃重复」。这说明它学到的是**序列级模板匹配**，
不是「把输入搬到输出」的**变量绑定**。

**口吃现象**（`小小小王`、`杜子子子子墨`）在纯复制模型上普遍存在，
说明**读出头无法稳定维持一个位置指针**——这正是复制所需的机制。

## 三、决定性实验 2：新配对绑定（关键区分）

把「名字」和「颜色」分开看：

- **名字见过 + 颜色见过 + 组合未见**（从 L4 语料里取真实出现过的名字，配一个语料中未出现的颜色）：
  **名字 3/12，颜色 3/12，两者都对 0/12**。

```
郝子墨/紫色 -> "郎子子墨，紫色。"      （名字错、颜色对）
雷敏/紫色   -> "雷�����…（连发到截断）"
宋建国/紫色 -> "宋建国国国华，下棋。"   （名字部分对、颜色错）
杜子墨/紫色 -> "杜子子子子墨，紫色。"   （名字带口吃、颜色对）
```

**这解释了 doc 12 与 doc 10 的矛盾**：

| | doc 12 的 probe3 | 本轮 L4 |
|---|---|---|
| 测试名字来源 | **30 词封闭集**，语料内反复出现 | 3 787 个名字，每个仅出现 2–3 次 |
| 语料内名字绑定 | 12/12（8 层） | — |
| 新名字绑定 | 未测（名字全在词表内） | **1/12** |

doc 12 测的是**封闭名字集上的记忆**：名字少、重复多，模型可以为每个名字分配状态维度，
表现为一张查找表。一旦名字集放大到 3 787 个（每个只出现 2–3 次），查找表失效，
**真实的组合绑定能力暴露为 ~0**。

> 注：L2 上「15/18 两者都对」的漂亮数字，同样来自那 30 个名字的记忆，
> 因为 `build/diag_binding_rate.exe` 用的 `小王/小张/小何` 正在 L2 语料内。
> 换成语料内不存在的新名字后，L2 是 **0/12**。

## 四、决定性实验 3：数据规模的确定收益

必须记录：**8.3× 数据有一个真实、可复现的收益——退化性重复消失了。**

| 同一测试（12 个分布内新名字） | L2 @200（2 133 篇，NLL 0.09） | L4 @400（18 038 篇，NLL 0.30） |
|---|---:|---:|
| 退化重复条数 | **4/12** | **0/12** |
| 名字 | 0/12 | 1/12 |
| 颜色 | 3/12 | 4/12 |

L2 的典型输出：`小何何何何何何。`、`小树树树树树…`（64 token 截断）
L4 的典型输出：`好的，我记住了。`、`童国华。`（语法正常，但内容错）

**⇒ 数据规模解决「说不成人话」，不解决「记不住/搬不动内容」。**

## 五、顺带发现并修复的架构一致性缺陷（重要）

固化 2 层时我把 `groupSource(2)` 写成 `{0,0}`（沿用 8 层「半组」规则），
但**新训练从零起时 `initialize()` 为每一层生成独立权重**。于是解码会把
**第 1 层丢弃、把第 0 层跑两遍**——**违反 I4（训练/推理同算子）**。

实测（L4 step400，同一输入）：

| 层映射 | 回答 |
|---|---|
| `0,0`（错误） | `童小龙，樱桃。`（全错） |
| `0,1`（恒等） | `王小军，紫色。`（名字错、颜色对） |

**修复**：`groupSource(n)` 改为

- `n >= 4`：两半分组 → 8 层得 `0,0,0,0,4,4,4,4`（**上一轮固定的部署配置，截到 2 层仍是 `{0,0}`**）
- `n == 2`：**恒等 `{0,1}`**（与训练一致）
- `n < 2`：恒等

并已在 `config_dump()` 中自证：

```
8 层 checkpoint 截断 -> layers=2/8 share=0,0,0,0,4,4,4,4   （不变）
原生 2 层 L4        -> layers=2/2 share=0,1                （已修）
```

> 纪律教训（第三次同类错误）：**「开关无效」的结论必须先证明开关真的生效**。
> 我第一次比较 `0,0` vs `0,1` 时两者输出逐字节相同，差点据此判定「层共享无影响」；
> 换一组输入后立刻出现差异。逐字节相同是**巧合**，不是证据。

## 六、为什么架构做不到（机制层解释）

当前读出是**固定线性投影，无查询**：

```
r = W_rs · s + W_rm · m        （s=128, m=512，每层）
```

- **绑定**需要在状态里存 `(键, 值)` 对，并在提问时按**键**取回**值**。
  固定线性读出头没有地址机制，只能靠状态维度**复用**（把不同名字编码到不同子空间）。
  这对 30 个名字可行（查找表），对 3 787 个名字不可行。
- **复制**需要把输入序列搬进状态，再按**位置指针**逐个吐回。
  口吃（`小小小王`）正是**指针不稳**的表现。

这两者都需要**可寻址的读写**（attention / 显式槽位 / 键值记忆），
不是靠加大数据或调 lr 能得到的。这与 doc 10 §六 的原始架构判定一致；
doc 12 的「数据问题」只适用于**流畅性**维度。

## 七、预登记判据 vs 实际（诚实记录）

doc 13 §三 预登记：「在**匹配训练 NLL** 的前提下比较 L2 与 L4」。

| 判据 | 目标 | 实际 | 判定 |
|---|---|---|---|
| 交叉注入「两者都对」 | ≥15/18 | 1/12（新名字） | ❌ |
| held-out 核心集 | >0/20 | 0/20 | ❌ |
| 退化性重复 | 消失 | **0/12** | ✅ |
| 复制类 | ≥4/8 | 0/8 | ❌ |

**必须承认的方法论缺口**：L4 @400 的训练 NLL 是 **0.30**，而 L2 @200 是 **0.09**，
**两者并未 NLL 匹配**，L4 在 400 步时仍在下降（300 步 0.63 → 400 步 0.30）。
因此「绑定没改善」这一条**带有「L4 可能还没训够」的保留**。

**但复制结论不受此缺口影响**：纯复制模型训到 **NLL 0.11**（与 L2 的 0.09 同档）
仍在语料外 0/5。**复制是架构限制这一条是干净的。**

## 八、下一步（按证据排序）

1. **可寻址读出**（针对绑定/复制的根因）：在读出 `r = W_rs·s + W_rm·m` 之上加一个
   **查询**——最小改动是让状态维护 k 个显式槽位，读出时按当前 token 做软寻址
   （单头 attention over slots）。这是唯一直接命中 §六 机制解释的方向。
2. **补足 L4 训练预算**再判定绑定（消除 §七 的保留）：L4 需要训到 NLL ≤0.09。
3. **解码侧重复抑制**（便宜、正交）：`greedy_step` 已有 `observe(r,value)` 钩子，
   可加 `TAO_REPEAT_PENALTY` / `TAO_NOREPEAT_N`，专治口吃，不需重训。
4. **两段式候选池输出头**：`buildHead2`/`set_head2` 脚手架已在，评测路径未写；
   但它只改**输出层候选生成**，不解决状态里的绑定问题，优先级低于 1。
