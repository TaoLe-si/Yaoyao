# 10 · 泛化能力诊断：瓶颈在「读出」，不在「写入」

> 2026-09-10 实测。全部数字来自本机 CPU 前向，零训练；复现命令见 §8。
> 本文只回答一个问题：**模型学不会「用上下文」这件事，到底是数据问题还是架构问题？**

## 一、结论摘要

1. **失败是分类别的，不是渐进的**。静态事实与措辞泛化已经学会；**上下文绑定、列表复制、新话题多轮恰好 = 0**。
2. **它不是欠拟合**。probe1 训练 NLL **0.00073**（417 epoch，语料已被完全记住），D/E/F 仍然 **0/6**。
3. **信息确实写进了递归状态**。固定名字只变颜色：状态里颜色的最近质心 LOO 可解码率 **33–58 %**（随机基线 8.3 %）；只变名字：**69–81 %**。
4. **但读不出来**。18 组「交叉注入」（名字与颜色都在词表内、但该配对在语料中从未出现）→ 名字与颜色**两者都对 0/18**。模型的回答永远是语料里已记住的 12 个配对之一（小王/红色、小张/紫色、小周/灰色、小林/蓝色、小陈/白色）。
5. **结构原因**：读出是 `r = W_rs·s + W_rm·m`——**与问题无关的固定线性投影，不含 query**。状态里有什么，读出都只能给出同一个线性像。这就是「信息在状态里但取不出来」的直接机制。
6. **尚未排除的替代解释**：probe2 语料只有 **19 篇**记忆配对、**7 篇**列表复制；模型用「记住 12 个配对」这条捷径就足以把训练 NLL 压到 0.20。**probe3 正是为消除这个解释而造的**（361 记忆配对 + 107 列表 + 90 重复），但它只训到 **step 26 / 配置 700 步，epoch 0，NLL 3.65**。→ 见 §6。

固定名字只变颜色 / 固定颜色只变名字，各 12 类 × 4 种措辞 = 48 个状态样本；取第一轮问答结束、提问之前的状态；用留一法最近质心解码 `m`。

**合起来：状态里有的东西，读出取不出来。**

## 五、结构原因

现行算子的递归与读出（`src/greedy_pipeline_grouped_model.hpp` `recurrent()`）：

```
s[j] += σ(a[j]) · (tanh(u[j]) − s[j])          a, u = W_a[x;s], W_u[x;s]
m[j] += σ(g[j]) · (tanh(v[j]) − m[j])          g, v = W_g[x;s;m], W_v[x;s;m]
r     = W_rs·s + W_rm·m                         <-- 固定线性读出，不含 query
x    += RMSNorm(r)
```

两条状态更新都是**对角、逐元素**的：没有跨维混合，也没有「针对某个 key 的擦除」。而读出是**与输入问题无关的固定投影**。

后果链条：

1. 上下文只能以**叠加**方式写进 d 维向量，没有寻址槽位；
2. 读出只能取这个向量的**固定线性像**，无法按 query 选择；
3. 于是「参数记忆里的高频配对」在读出端压过「刚刚写进去的绑定」——**这正好就是观测到的现象**：状态里有颜色信息（LOO 33–58 %），回答却是记忆里的配对。

这也解释了为什么 A/C 类能学会而 D/E/F 学不会：**A/C 只需要参数记忆，D/E/F 需要内容寻址。**

## 六、尚未排除的解释与最便宜的决定性实验

**反面解释**：probe2 只有 19 篇绑定样本。用「记住 12 个配对」这条捷径就能把训练 NLL 压到 0.20，**梯度没有理由去学复制机制**。在这个解释下，D/E/F 的 0 是数据问题。

**这个解释无法用现有 checkpoint 排除**，但可以便宜地排除：

> **跑完 probe3 的训练。** probe3 有 361 篇记忆配对（probe2 的 19 倍）、107 篇列表复制、90 篇重复复制，配置 700 步。
> - **若 probe3 在同等 NLL 下学会复制/绑定** → 是数据问题，架构不必动，把力气放到数据管线。
> - **若 probe3 仍抄不出来** → 架构问题，优先做 H2。

判据必须**预先登记**，避免事后解释：probe3 训到训练 NLL ≤ 0.3（与 probe2 持平）时，§三 的交叉注入绑定率若仍为 **0/18**，则判定为架构问题。

### 6.1 执行结果（2026-09-11 补记：该实验已执行，结论为「数据问题」）

上文登记的判据**当时并未执行**（probe3 只训到 26 步）。补跑后（`dual-state-3`，slots=32/width=32，未改架构）：

| | probe2 @113 步 | **probe3 @100 步（第 96 步跨过 NLL ≤ 0.3）** |
|---|---:|---:|
| 名字抄对 | 5/18 | **18/18** |
| 颜色抄对 | 4/18 | **10/18** |
| **两者都对** | **0/18** | **10/18** |

其中 **8/14 是语料中从未出现过的名字×颜色新组合**，因此不是记忆而是组合泛化。

**判定：反面解释成立——是数据问题，不是架构问题。** probe2 只有 19 篇绑定样本，梯度没有理由学复制机制；probe3 的 361 篇足以让同一套算子学会绑定。

本节的「优先做 H2」推论**据此撤回**。H2R 后续仍被实现并做了 A/B（见 12 号文档）。**锁定训练水平后两臂无可测泛化差异**：各自最好水平下绑定率 13/18 vs 16/18（p = 0.402）、held-out 核心集 8/20 vs 7/20（p ≈ 1.0）、复制 2/8 vs 0/8（p = 0.47），无一项显著且方向不一致。H2R 账面更便宜（每 token MAC −37.3 %、常驻 −41 %）但**训练损失下限更高**（0.08 vs 0.047）。

**更精确的残余缺陷**：模型稳定绑住**第一个槽位**（名字 18/18、held-out 6/6），第二槽位只绑住一半（颜色 10/18、held-out 喜好 0/6）；复制类任务（list/repeat）仍为 0/8。详见 12 号文档。

## 七、候选架构对策（在 I1–I5 下）

先看现状的成本结构（`src/dual_state_config.hpp` schema 逐项算）：

| 组成 | 每层 MAC | 占比 |
|---|---:|---:|
| s 组（`s.candidate`/`s.gate`，各 d×s + s×s） | 163,840 | 9.8 % |
| **m 组**（`m.candidate`/`m.gate`，各 **m×d + m×s + m×m**） | **1,179,648** | **70.6 %** |
| 读出（`read.s` d×s + `read.m` **d×m**） | 327,680 | 19.6 % |
| **合计** | **1,671,168** | |

**关键事实：现状每层有 1,441,792 个三值参数（m 组 1,179,648 + `read.m` 262,144）只用于「产生一个候选向量、一个门、读出这个向量」。** 增量规则用 d_k=64 的 k/q 投影就能替代它。

| 编号 | 改动 | 直击 | 每层 MAC | 每 token MAC | 三值参数 | int8 常驻 / tps | 会话状态 | 重训 |
|---|---|---|---:|---:|---:|---:|---:|---|
| 现状 | `dual-state-3` | — | 1,671,168 | 21,757,952 | 21,757,952 | 22.11 MB / 845 | 20 KB | — |
| **H1** | 乘性门控读出 `r = W_rs·s + W_rm·(m ⊙ q)`，`q=σ(W_q·xn)` | 让读出依赖输入 | **+15.7 %** | **+9.6 %** | **+9.6 %** | **24.24 MB / ~771** | 不变 | 是 |
| **H2R** | **m 组整体替换为增量规则矩阵记忆**（d_k=64）：`m ← m − β(mk)kᵀ + βvkᵀ`，读 `o = mq`；**s 组保留**作门控 EMA | **写入定点擦除 + 读出显式 query** | **−60.8 %** | **−37.3 %** | **−41.0 %** | **13.09 MB / ~1427** | 1 MB | 是 |
| H2R′ | 同上但 d_k=128 | 同上（容量更大） | −47.0 % | −28.9 % | −38.6 % | 13.59 MB / ~1375 | 2 MB | 是 |
| H2A | 增量规则**叠加**在现有 m 组之上（不替换） | 同上，保留旧容量 | +27.5 % | +15.1 % | +12.1 % | 24.8 MB / ~754 | 1 MB | 是 |
| H3 | 固定窗口（W≈64）局部精确复制通路 | 复制类任务 | +≈2 % | +≈1 % | +≈1 % | 略增 | +128 KB | 是 |
| H5 | 复制/指针头 | 复制类任务 | 小 | 小 | 小 | 略增 | 不变 | 是 |

**结论修正（本节初稿把 H2 写成「比 H1 贵」，是错的）**：

- **H1 不是最小改动**——它**增加** 9.6 % MAC 与 9.6 % 常驻字节（tps 845 → ~771），换来的却只是「读出被输入门控」。这个门只依赖 `xn`，是对**状态维度**做软选择，**仍然不能对「条目」寻址**；对叠加编码的记忆，它大概率不够。
- **H2R 反而更便宜**：每 token MAC −37.3 %、三值参数 −41.0 %、常驻 −41 %（带宽墙下 tps 845 → **~1427**，+69 %）。原因是现状的 m 组用了 **6 个稠密矩阵**（2×512×512 + 2×512×128 + 2×512×512）只为了产出一个候选与一个门，而增量规则的核心算子 `mk`/`vkᵀ` 只是 512×64。
- H2R 的代价：① 容量下降 41 %（可用 d_k=128 或加宽 v 回购一部分）；② **输出头在每 token MAC 中的占比从 38.6 % 升到 61.5 %** → S5（候选池词表头）的优先级被这一步抬高；③ 会话状态 20 KB → 1 MB（仍与序列长度无关，符合 I3）；④ 训练需要 chunkwise(WY) 实现（工作量最大的部分）。
- 全部候选**不违反 I1**（无 FFN）、**I2**（新增投影仍是三值 + 行尺度）、**I3**（状态仍与序列长度无关）。
- **H2R 是唯一在结构上直接对应「信息在状态里但读不出来」的改动**：同时给了读出 query 与写入定向擦除。

## 九、诚实边界

- 全部结论来自 **≤ 969 篇、≤ 39 k token 的微型语料**上的探针模型；不能直接外推到生产模型规模。
- probe2 处于 **epoch 14 / 训练 NLL 0.20**，仍在拟合中；「读出失效」的结论只在这个训练点上成立。
- 生产的 step 1512 模型**已完全退化**（对任何输入输出 64×「好的」后截断），不提供任何信息。
- §四的「距离比」与 LOO 是**线性**判据；若信息以非线性方式编码，会被低估。但 LOO 已远超基线，不影响主结论。
- probe1 与 probe2 的差异同时包含「数据量」与「过拟合程度」两个变量，本文没有把两者分开。

## 十、H2R 实现记录（Phase 1，已完成并验证）

**算子身份**：`dual-state-4-noffn-delta-mem-input-sqrt-d`（默认构建仍是 `dual-state-3-noffn-input-sqrt-d`，两者由 `TAO_DELTA_MEM` 宏区分，**互不兼容**）。

### 10.1 算子规格

```
xn = RMSNorm(x, input.norm)

// s 组：原样保留（门控 EMA，负责近因/衰减）
u = W_su·xn + W_sus·s + b_su
a = W_sa·xn + W_sas·s + b_sa
s <- s + sigma(a) * (tanh(u) - s)

// 增量规则矩阵记忆（替换整个 m 组）
k = W_k*xn   in R^64          // mem.key
q = W_q*xn   in R^64          // mem.query
v = W_v*xn   in R^512         // mem.value
beta = sigma(<w_b, xn> + b_b) // mem.beta / mem.beta.bias，标量
k^ = k / (||k||_2 + 1e-6)
M <- M + beta * (v - M k^) (x) k^   // M in R^{512x64}，定点擦除 + 写入
o = M q                             // 先写后读
r = W_rs*s + o
x <- x + RMSNorm(r, read.norm)
```

### 11.2 正向与反向（含勘误）

前向（每 slot、每层）：

```
k^ = k/(||k||+eps)
a  = M k^
u  = beta (v - a)
M' = M + u k^T
o  = M' q
```

反向。记 `do = dL/do`、**`dMout = dL/dM'`**（M' 还要当下一个时间步的 M，所以它自带梯度），
`c = q·k^`、`p_i = Σ_j dMout[i,j] k^[j]`、`du_i = do_i c + p_i`、`e = do·(v-a)`：

```
dbeta    = Σ_i du_i (v_i - a_i)
dv_i    += beta du_i
dM[i,j] += do_i q_j + dMout[i,j] - beta du_i k^[j]
dk^[j]  += beta q_j e + Σ_i dMout[i,j] u_i - beta Σ_i du_i M[i,j]
dq[j]   += Σ_i M[i,j] do_i + k^[j] beta e
```

**单步时 `dMout = 0`，全部退化为只依赖 `c`、`e` 两个 per-slot 标量的极简形式**——即最初写在注释里的那组公式。化简成立：
`a = M k^` 的贡献被解析折进 `dM` 与 `dk^`，**不需要保存 M'**（`dMout` 就是 M' 自己的梯度缓冲），**也不需要 a 的梯度缓冲**（前向的 `a` 只用于算 `e`）。

> **勘误（由 §11.3 的校验抓出，三处都是真 bug）**
> 1. 最初写的 `dM[i,j] += do q + beta do c k^` 与 `dk^ += beta(q e + c g)` **符号写反**，应为**相减**（来自 `a = M k^` 那一支）。
> 2. **`dq` 完全漏写**（解析梯度恒为 0）。
> 3. 跨步复用时还漏了 `dMout` 的三项。漏掉 `dMout` 的典型症状是：**`mem.beta` 的解析梯度恰好是有限差分的 1/n**（n = 时间步数）——局部项对、跨步项全缺。

### 11.3 有限差分校验（`build/test_delta_grad.exe`）

配置 `layers=1 d=16 s=8 m=16 dk=4 vocab=272 slots=2`，对 13 个张量各取 3 个下标做中心差分（`h=5e-3`）。
损失用固定系数与 logits 的内积。**用多个时间步**是为了让 M 真正跨步累积，从而校验 `dMout` 那一支。

| 时间步 | 结论 | 最差绝对误差 |
|---:|---|---:|
| 1 | 通过 | 1e-3 量级 |
| 2 | 通过 | — |
| 3 | 通过 | 4.6e-3（`input.norm`） |
| 5 | 通过 | — |
| 8 | 通过 | — |

判据用**绝对容差** `2e-3 + 0.05·|fd|`：`|L|~10`、`h=5e-3` 时中心差分的噪声底约 `eps·|L|/h ≈ 2e-4`，纯相对误差对接近 0 的分量没有意义。
修复前 `input.norm` 的绝对误差是 **5.5**，修复后 **7.8e-4**。

### 11.4 端到端训练（probe3 语料，同数据同位置数）

| | dual-state-3（现状） | H2R（dual-state-4） |
|---|---:|---:|
| 配置 | 16 slots / width 16 | 16 slots / width 16 |
| updates | 12 | 12 |
| positions | 20 737 | 20 737 |
| 墙钟 | 10.3 s | 12.0 s |
| 吞吐 | 2 013 pos/s | **1 728 pos/s** |
| NLL | 16.012 → **7.394** | 15.985 → **8.782** |

**H2R 能训练**（NLL 单调下降 16.0 → 8.8），但在这个预算下**收敛落后于 dual-state-3**，且**吞吐反而低 14 %**——
尽管 H2R 每 token MAC 少 37.3 %（见 §10）。原因见 §11.5：矩阵状态的访存量远大于向量状态。
这是**单种子、等步数**的比较，不构成架构判决。

### 11.5 显存约束（必须记住）

H2R 每 slot 每层状态是 `dv×dk = 512×64 = 32 768` 个浮点，而 dual-state-3 是 `m = 512`，**大 64 倍**。
tape 要为每个时间步保留一份（值 + 梯度），于是激活显存 ≈ `slots × width × layers × dv × dk × 16 B`。

- `slots=32 width=32` → 约 4 GB → **失败**：`PROBE_FAIL device not ready`
- `slots=16 width=16`、`slots=8 width=8` → 正常

**缓解方向（未做）**：反向并不需要 `M'` 的**值**（只用它的梯度 `dMout`），前向的 `M` 值可以用梯度检查点在反向时重算，可把激活显存从 `O(width)` 降到 `O(1)`。
