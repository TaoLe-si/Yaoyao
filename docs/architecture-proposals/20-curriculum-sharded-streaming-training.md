# 20 · 训练方法：课程式分段积累（精 → 混合 → 干扰）+ 分片流式

> **本文推翻 doc 17/18/19 里「一次性 18 B token 大循环」的 transformer 式训练设想。**
>
> 用户定调：**因为支持续训，完全没必要按 transformer 模式训练**。
> 本架构是**内容寻址的增量记忆**，更合适的是：
> **先学最优最精的部分 → 混合训练 → 干扰训练**，并以**分片、流式**方式推进。

---

## 一、为什么不能照搬 transformer 的训练法

| 维度 | Transformer | 本架构（dual-state + H2R 增量记忆） |
|---|---|---|
| 知识载体 | 全部压在三值权重里，靠**海量数据反复冲刷** | 权重 + **逐层 delta-rule 记忆矩阵 `M`**（内容寻址，可增量写入） |
| 数据用法 | 一遍大循环，shuffle 全局，靠 epoch 数堆 | **可分段、可续训**，段与段之间靠检查点衔接 |
| 遗忘 | 换分布易灾难性遗忘 | 记忆是**写入式累加**，配合课程顺序可控 |
| 显存 | 全参数 + Adam 状态常驻 | **已实现主存替代**（20 B/参数 → 8 B/参数） |

**关键点**：我们的瓶颈从来不是「token 不够」，而是 **泛化**——已实测出模型在 3 787 个名字上
退化成**查表**（doc 14/16）。**单纯堆 token 治不了查表**，甚至会加重它。

所以正确的做法不是「更多数据」，而是**有序的数据**。

## 二、三阶段课程

### 阶段一：精（Core / Refined）

**目标**：用**最少、最干净、信号最强**的数据，把核心表示立起来。

- 数据：**最高质量子集**。代码场景 = 文档齐全、命名规范、可独立成篇的代码；
  自然语言 = FineWeb-Edu 里的高分段。
- 规模：**小**（百万～千万 token 量级即可起步）。
- 停止条件：**验证 NLL 饱和**（连续 N 次检查无改善），而非固定步数。
- 判据：核心任务探针（我们已有的 binding / copy / 列表复制）**先在小实体集上达标**，
  再换**大实体集 held-out** 复测——防查表（R6）。

> 对应"textbooks are all you need"思路：精数据把**结构**先学对，后面加噪声才不跑偏。

### 阶段二：混合（Mixed）

**目标**：在已立好的核心上**扩展分布宽度**。

- 数据：代码（多语言）+ 自然语言，按比例混合（代码为主时 85/15）。
- 从阶段一检查点**续训**（`RESUME_DIR`）。
- **关键**：混合比例要**渐变**，不要一步跳到目标配比——避免核心被冲散。
- 判据：held-out 泛化指标**不得低于阶段一**；若下降，说明混合过快或噪声过多。

### 阶段三：干扰（Interference）

**目标**：**逼模型判别，而不是记忆**。这是治查表的正解。

- 数据：**刻意注入混淆项**：
  - 名字类：同姓氏、同名字、一字之差（`邬晓东`/`邬晓梅`、`孔桂英`/`卢桂英`）
  - 问法类：共享前缀但答案不同的问句（这正是 L5→L6 踩过的坑）
  - 代码类：近似但语义不同的代码片段、易混 API
- 原理：当**记忆无法区分**训练样本时，模型被迫学**可判别的特征**（结构/关系），
  而不是记 `输入→输出` 的查表映射。
- 判据：**大实体集 held-out 上的泛化必须上升**；同时语料内记忆可略降（这是好事）。

> 阶段三与阶段二的差别：阶段二是"更宽"，阶段三是"更难"。
> 干扰项必须是**分布内但可判别**的——纯随机噪声没用。

## 三、分片 + 流式

### 3.1 为什么要分片

| 问题 | 现状 | 分片后 |
|---|---|---|
| 内存 | `train_noffn_probe.cu` 把整个 `train.bin` 读成 `std::string` | **一次只持有一个分片** |
| 规模上限 | 受内存限制（文档数上限 1<<20） | **无上限**，分片数任意 |
| 续训粒度 | 只能整段重跑 | **按分片续训**，崩了只丢当前分片 |
| 课程控制 | 无 | **分片即课程单元**，可指定每片训练步数 |

### 3.2 分片格式

```
data/<corpus>/
  shard_00000.bin        每个 = 一个完整 TLP2 文件（与现有格式完全兼容）
  shard_00001.bin
  ...
  shard_manifest.tsv     分片清单：序号 / 文件名 / sha256 / docs / tokens / 阶段标签
  curriculum.tsv         课程表：阶段名 / 分片范围 / 每片步数 / 学习率
```

`curriculum.tsv` 示例：

```
# stage  shards      steps_per_shard  lr
core     0-9         400              0.001
mixed    10-39       300              0.0008
interfere 40-59      300              0.0005
```

### 3.3 流式读取

需要新增**增量读取器**（现有 `read_bpe_pilot` 会把全部 doc 读进 vector）：

```cpp
// 读至多 max_docs 篇，返回已读数量；EOF 时返回 0
size_t read_bpe_pilot_shard(std::istream& in, const std::string& expected,
                            size_t max_docs, std::vector<std::vector<Token>>& out);
```

- 每个分片 = 独立 TLP2 文件，**自带 header**，所以天然可流式。
- 训练器按 `curriculum.tsv` 顺序：**打开分片 → 训练 N 步 → 存检查点 → 关文件 → 下一片**。
- 全部分片走完 = 1 个"课程轮"；可重复多轮（第二轮起用不同 shuffle 种子）。

### 3.4 续训语义

- 每片结束存 `opt_state.bin` + `final.dsb`（已实现）。
- 续训参数：`RESUME_DIR=<上次输出目录>`，并**记录已消费分片序号**，
  避免重复消费或跳片（写进 `progress.tsv`）。
- **数值语义**：续训恢复权重 + Adam 动量/方差 + 步数；数据游标从新分片起点开始
  （故非逐样本确定性，权重恢复是精确的）。

## 四、与已有实测的衔接

| 已有结论 | 在本方法里的作用 |
|---|---|
| L4 泛化退化 4/12→0/12（数据量 8.3×） | **证明堆数据不治查表** → 阶段三的存在理由 |
| L6 修好两问合一（9/10/8） | **证明有序/定向数据有效** → 课程法的可行性依据 |
| 纯复制模型 NLL 0.11 仍 0/5 语料外 | 记忆 ≠ 泛化，阶段三必须测 **held-out** |
| H2R 是唯一能抄内容的机制 | 阶段一应先让 **H2R 记忆**立起来 |
| 训练本身不可重复（±1e-5） | 课程判据必须用**多次运行的包络**，不能比单次 |

## 五、0.9B 配置（按 H2R schema 重算）

> doc 17 §2.3 用的是 **ds3** 的每层公式（含 `m.candidate/m.gate`，26.75 M/层），
> 对 **H2R（DELTA_MEM）** 不适用。按 `dual_state_config.hpp` 的 DELTA_MEM 分支重算：

每层张量（d=2048, s=512, m=2048, dk=64）：

| 张量 | 形状 | 元素 |
|---|---|---:|
| s.candidate.x / s.gate.x | 512×2048 ×2 | 2 097 152 |
| s.candidate.s / s.gate.s | 512×512 ×2 | 524 288 |
| mem.key / mem.query | 64×2048 ×2 | 262 144 |
| mem.value | 2048×2048 | 4 194 304 |
| read.s | 2048×512 | 1 048 576 |
| **三值小计** | | **8 126 464** |
| bias/norm（非三值） | | 7 169 |
| **每层合计** | | **≈ 8.13 M** |

| 配置 | 每层 | 层数 | 总参数 |
|---|---:|---:|---:|
| d=2048 s=512 m=2048 vocab=65536 | 8.13 M | **94** | **≈ 0.90 B** |
| d=2048 s=768 m=2048 vocab=65536 | 10.36 M | **74** | ≈ 0.90 B |
| d=2048 s=1024 m=2048 vocab=65536 | 12.85 M | **60** | ≈ 0.90 B |

> **建议 d=2048 / s=1024 / m=2048 / vocab=65536 / L=60**：
> 层数最少（本架构逐层串行，层数直接放大推理延迟），
> 且 60 层与 transformer 常见深度可比，便于"对标"叙事。

**显存**（主存替代已实测可用）：GPU 侧 8 B/参数 → 0.9B ≈ **7.2 GB**，
配 bf16 梯度降到 ≈ 5.4 GB。
