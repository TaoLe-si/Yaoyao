# 底层架构建议的评估方案

> 范围：只评估**底层架构**（数据布局 / 内核 / 线程 / 内存与延迟 / 数值一致性 / 算子身份）。

## 二 · 统一验收四件套

任何一条建议合并前必须同时给出：

1. **吞吐**（3 位有效）＋ 线程数 ＋ 亲和性；
2. **数值一致性**：bitwise（`checksum=2901` 不变 + 逐张量 identity 测试）**或**明确误差界；
3. **常驻字节**（运行时实测，不是从 DSB 推算）；
4. **可回退**：旧路径保留在同一二进制内，可一键切回。

> 缺任何一项不合并。

## 三 · 前置：基础设施事实复核（0 成本，1 天，**先做**）

### 3.1 复核已完成，一处需要更正

README §三.9 称「`update()` 每步对**每个**张量做全量 `grad.host()` 回读；`project()` 全量 host 扫描」。

【核实】**在生产路径上不成立**：`src/dual_state_sorted_trainer.cuh` 的 `update()` 与 `project()` 都以 `#ifdef TAO_GPU_HEALTH` 分叉，而 `src/train_yaoyao_graph_gpuval.cu:3` 定义了 `TAO_GPU_HEALTH`（`train_noffn_fresh.cu:7` 包含该文件），因此走的是 `GpuHealth::add()` → `ds_health` 核（`src/gpu_health_reduce.cuh:4`）的 **GPU 侧归约**，`finish()` 只回读 **4 B（bad）+ 8 B（sum）**。那两个逐元素 `host()` 分支是未编译的死代码。

**后果**：04 号文档 §四 改造清单的**第 1、2 行应删除**（或降级为「可选清理」）；训练器扩容的真正阻碍是**每参数 12 B 的优化器状态**（master + moment + variance，`SortedGpuTrainer` 构造处）与**加载器上限**，不是逐步 D2H。

附带一处陈旧注释：`train_noffn_fresh.cu:3` 写「cosine decay 1700->2200」，同文件第 111–115 行实际是 `decay_begin=1500`、`hard_target=2000`。

## 四 · 逐项评估方案

### S3 · 判定实验 —— ✅ **已完成（2026-09-10）→ H-BW 成立**

- **判定**：`8线程/2线程 = 1.113×` ≪ 2× → **H-BW（带宽受限）**。带宽封顶 18.68 GB/s，且 `18.68e9/22.112e6 = 845` 与实测 844.8 吻合到 3 位有效。
- **工具**：`src/benchmark_noffn_s3.cpp` + `scripts/build_s3.bat` → `build/benchmark_noffn_s3.exe`（插桩）/ `benchmark_noffn_s3_plain.exe`（无插桩）。用法 `<dsb> <线程列表如 1,2,4,8> [分发阈值]`。
- **结果**：4 线程 844.8 ± 11.7 tps（**相对冻结基线 2 线程 +11.1 %**）；8 线程 832.3（0.99×）；16 线程更差；checksum 在 1/2/4/6/8/16 线程**全部 = 2901**。
- **副产物**：词表头 27.67 G MAC/s（L3 命中）vs m 更新组 18.07 G MAC/s（走 DRAM）——S4 的理由被实测加强。
- **后续影响**：S6 降级；S1 升为第一位；S2 已随 S3 一并实现完毕（+11 % 即其全部收益）。
- **完整证据**：08 号文档。

### S1 · 2-bit 打包常驻 + 内核内 `vpermb` 展开（最高优先）

- **现状核实**：`src` 内**没有任何** `vpermb` / `vpmultishiftqb` / packed-2bit 代码 → **完全未开工**。
- **命名陷阱**：`greedy_pipeline_grouped_model.hpp:19-21` 里的 `packed` / `PipelineRows` 指的是**已展开的 int8 行**，不是 2-bit 打包。改造与验收时不要误判为「已完成」。
- **评估方法**：
  1. 常驻字节：`greedy_pipeline_grouped_model.hpp:28` 的 `weight_bytes()` 运行时实测（它已区分 float 与 int8 两口径，需再分出 packed）；
  2. 内核级数值：`build/test_cpu_ternary_avx2.exe <dsb>`（现有基准 **PASS: exact row ternary AVX2 vs expanded FP32 including tail**）扩一组 packed 变体；`build/test_packed_prefix.exe` / `test_packed_lut_prefix.exe`（现有输出 `correct=192/192 parity=192`）作前缀路径对照；
  3. 端到端：`benchmark_noffn_decode.exe` 的 **FORCED checksum 必须仍是 2901**，5 轮全同。
- **判据**：常驻 22.1 → **≈5.8 MB**；FORCED tps **≥1700**；checksum **=2901**。
- **证伪**：checksum 变化即实现错误（16 列分组 / lane 折叠 / 累加顺序未保持），**不是**可接受的数值差异。
- **成本**：3–5 天（前置 S3 判 H-BW）。
- **价值**：**唯一一条不改数值、不需重训、可一键回退的大杠杆** → 排在实现序列第一位。

### S2 · N 线程行池

- **现状核实**：只有 `CpuRowParallelExecutor`（caller + 1 worker），**无** N-worker 池。
- **评估方法**：新建 `src/cpu_row_parallel_pool.hpp`；1/2/4/8/16 线程扫描；绑定 8 个物理核（避免 SMT 争抢）。
- **判据**：多线程 vs 单线程 **bitwise 一致**（复用 `build/test_advance_row_parallel_byte.exe <dsb>` 与现有 identity 测试）；checksum=2901；S1 完成后 **3000–6000 tps**。
- **注意**：只有 ≥最小行数的投影才并行；RMSNorm 归约与状态更新是串行段 → 分解计时会暴露 Amdahl 上限。
- **证伪**：8 线程相对 2 线程不涨 → 已在 DRAM 带宽处饱和，**停止加线程**，转 S4。

### S4 · 层维复用（**零训练代理实验**）

- **方法**（03 号文档 §六方案，正确）：写一个**离线替换脚本**，把现有 `step_1512/final.dsb` 中 Reuse 层的权重替换为组内 Full 层权重，产出一份「伪 S4 DSB」，然后只测两个数：`dsb_ledger.mjs` 的**唯一字节**与 `benchmark_noffn_decode.exe` 的 tps。
- **判据**：唯一 int8 字节 **≤14 MB**（目标：装进 16 MB L3）；tps 落进 **8000–15000** 区间（须注明是否叠加 S1/S2 口径）。
- **能力边界（须写进报告）**：该代理实验**不能**说明质量。质量属训练项，本轮不评估；代理实验只回答「值不值得开工」。
- **风险**：8 层只剩 2–4 份独立参数。

### S5 · 候选池词表头（**零训练诊断**）

- **零训练诊断**：在固定验证集上用现有 step_1512 统计 **argmax 落在 top-簇候选内的比例**，以及 top1/top2 分数差（02 号文档已测得顶端很平，约 5.6 %）。
- **产出形式**：一条 **「覆盖率 vs 头部流式字节」曲线**，而非单个 tps 数。
- **判据**：若要求质量无损，需覆盖率 ≥99.9 % 且保留全词表回退路径（`greedy_head_observe` 不得删除）；否则必须训练期同域（I4），成本翻倍。
- **注**：输出头占 38.6 % MAC / 37.3 % 字节，是最大单项。

### S6 · int8 激活 + `vpdpbusd`（**零训练误差界**）

- **方法**：离线把激活按 32/64 分块量化（零点 128、带块 scale），在固定验证集上算 logits 偏差与 **argmax 翻转率**。
- **判据**：先出误差界；**argmax 翻转率 >0 即必须做激活 QAT**（I4 要求训练期原样模拟），否则不能上线。
- **依赖**：仅在 S3 判为 H-UOP 时启动。

### S7 · Engram（**基础设施侧，零训练**）

- **方法**：合成一张 33.5 MB 与一张 1.6 GB 的表，测 **24 次独立随机访问**在有预取 / 无预取下的每 token 延迟；再测 4 KB 页 vs 2 MB 大页的差异。
- **判据**：无预取应观察到 **≈2.4 µs/token（≈400 tps 上限）**；有预取应 **<10 %** 占比。若测不出这个量级差 → 04 号文档的延迟成本模型不成立，须重估。
- **必查前提**：本机能否启用 `MEM_LARGE_PAGES`（需 SeLockMemoryPrivilege）—— 不能启用则 E4 缓解手段失效。
- **依赖**：加载器上限放开（见 L）。

### L · 加载器上限与 mmap 路径（扩容前提）

- **现状**：见 §3.2 行号。对本模型当前影响为 **0**。
- **评估方法**：构造 >512 MB 与 >1e8 元素的合成 DSB，确认抛错点与失败信息；改造为 mmap 后复测 `LOAD seconds` 与 RSS。
- **判据**：加载 RSS 不随表大小线性增长；`LOAD seconds` 不劣于当前 0.0992 s。

### S-extra · `s→m` 依赖错位

- **论文依据（已核实）**：§2.4.1 Single-Pass mHC 同一手法（`X_{l+1}=B_lX_l+C_lF_l(A_{l-1}X_l)`），原文称 *"this shift incurs negligible performance degradation"*，且**预训练仍保留多趟实现**，融合只用于部署。→ 有先例，但对本项目仍属**新算子**。
- **评估方法**：改 `dual_state_config.hpp` + CPU/CUDA 双路径；用分解计时看 s 段与 m 段能否并成一遍遍历。
- **判据**：目标收益 5–15 %；**数值会变（非 bitwise）** → 必须给误差界 + 新 operator id。

### D · 死路清单的复现（防止重复投入）

02 号文档 §五 的 6 条已否掉路线，评估方式不是重试，而是**把否证固化成可复跑脚本**：DSB 字节账、稀疏度与 α 极差已由 `dsb_ledger.mjs` 直接产出；「整模型常驻 L3」的否证已由常驻口径 22.1 MB > 16 MB L3 直接给出。
