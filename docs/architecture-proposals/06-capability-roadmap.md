# 能力与产品路线（非速度项）

> 速度线见 02/03/04 号文档。本文件收集**与 token/s 无关但决定项目价值**的事项，并明确标注它们各自的代价与验收方式。

---

## 一、先摆证据：当前的能力瓶颈不在架构

| 证据 | 观察 |
|---|---|
| probe 小语料模型（`src/train_noffn_probe.cu`，独立小语料、20 步 warmup） | step 50 已能正确回答「北京」「2」「I like studying.」，能记住「小林」「蓝色」 |
| 生产模型（5,953,644 token 语料，step 1512，val NLL 6.1065） | 生成仍循环退化 |

结论：**同一套算子、同一套反向传播，缺的是数据规模/混合与训练预算**。因此下面按「每单位算力换来的能力」排序。

> 【边界，DOC5】**这里不能再写成「论文第 5 章也是这个结论」**。论文第 5 章讲的是**后训练**（post-training）收益几乎全部来自数据与环境管线，而本项目处在**预训练**阶段，两者的数据/算力形态不同。这是**类比，不是引用**。
> 而且本节的证据本身有缺口：probe 的失败分类显示，**同一份语料内的记忆与措辞泛化可以学会，但上下文内容复制、换话题多轮、新列表项这三类始终学不会**——这三类恰好指向**架构**（见 10 号文档），不能笼统归给数据量。

## 二、C1 · 优化器分工（低成本，先做）

- **现状**：所有参数共用 AdamW（master + moment + variance = 12 B/参数）。
- **建议**：按论文分工——矩阵类用 Muon 风格（本模型矩阵是三值 master，可先只用「行归一化/RMS 重标定」的轻量版）；**嵌入表与预测头用 Nesterov 动量 + Sinkhorn 平衡**（K=11、τ=1e-3、γ=0.18，lr ×5）；norm/bias/scale 保持 AdamW。
  > 【补，DOC6】旧文漏了 Muon 的**动量 0.95 / 权重衰减 0.1 / RMS 重标定系数 0.18**（论文 §4.2.2）。0.18 不是装饰：Muon 的更新天然带尺度漂移，不做 RMS 重标定会让三值投影后的行尺度 α 分布进一步收窄。
- **动机**：共享 embedding + 输出头占全部参数约 38.5 %，其更新尺度问题（三值投影后的 α 分布很窄，实测 embedding 行尺度极差仅 2.16×）使统一的 AdamW 很难同时喂好「大表」与「小矩阵」；Sinkhorn 的行/列 RMS 等化正好针对这一结构。
- **代价**：训练器改动中等（per-tensor 优化器分派 + 一份动量缓存，**顺带把优化器内存从 12 B/参数降到约 5 B/参数**）。
- **验收**：同等步数下固定验证 NLL 不劣化；embedding 行尺度分布与更新范数曲线入档。

## 三、C2 · 会话状态持久化与降精度

- **现状**：每会话 20,480 B（8 层 × (s=128 + m=512) × float32）；SCP 已存在但**恢复脚本没有官方入口**（现状属于「推定用法」）。
- **建议**：① 状态支持 **fp16/fp8** 保存（论文对 SWA KV 保持 FP8 而 main KV 用 FP4 的做法可类比：s 敏感、m 可粗）；② 明确 `state.scp` 的恢复入口与校验（与检查点同一套 identity 纪律）；③ 按论文的持久 KV 分层思想做「热池/冷池 + TTL」。
- **收益**：会话恢复从「重新 prefill prompt」变成「一次加载 20 KB」——这是本项目对长对话场景最便宜的体验提升。
- **验收**：恢复后 32 步贪心与不中断会话 **bitwise 一致**（或给出误差界）；恢复耗时与状态字节入档。

## 四、C3 · 深度旋钮（论文 reasoning effort 的类比）

- **论文**：prompt 前置 effort 标量 1–100 控制推理长度，收益前置（60–80 档已拿到大部分），25→100 精度 67.1→76.3 但 token ×2.5。
- **本项目**：每 token 算力固定、无思维链，能对应的是**深度**。做法：训练期随机丢弃 Reuse 层（让它对「少用几层」鲁棒），部署时 8/6/4 层三档。
- **前置条件**：C3 依赖 03 号文档的层维复用（有 Reuse 层才谈得上丢）。
- **收益**：**这是本项目唯一能同时提高速度与保留质量的旋钮**（少算层数 = 少读权重），比 int8 激活路线更符合 I1/I4。
- **验收**：三档各自的 token/s 与 NLL/BPB 曲线（应呈现「收益前置」的形状）。

## 五、C4 · 数据与环境管线（**能力瓶颈的真正所在**）

- **任务三元组**：论文的 (problem, environment, verification system) 可直接映射到本项目的「符号推理课程 + 确定性验证器」：例如「记住并复述一个随机注入的事实」「多步状态追踪」「算术与字符操作」——**每类都有程序化验证器**，可以无标注生成海量样本。
- **难度标定**：用「难度（长度/干扰项数）」与「正确率」两维给任务打分，把语料按课程比例混合。
- **规模阶梯**：5.95 M token → 50 M → 500 M，配合**固定验证集**与 sealed 任务集；每次扩容单独成轮。
- **反 hack 质检**：检查语料是否能让模型靠表面线索拿分（对应论文的独立质检 agent）。
- **验收**：固定验证 NLL/BPB + 20 条探针 + 退化指标；sealed 任务集只在决策点开一次。

## 六、C5 · 浅层 prefill（CED 类比，只影响 TTFT）

- 论文用 CED 把 prefill 减半（decoder 层复用 encoder 末层隐状态生成 KV）。
- 本项目没有 KV，但可以问：**prompt 是否必须走满 8 层？** 若浅层只负责局部特征，则 prompt 前 k 层可用更便宜的处理（例如只用 s 分支、跳过 m 更新）。
- **收益仅限 TTFT**（每 token 吞吐不受影响）；**风险高**（不变量 I3/I4：状态更新路径必须训练期模拟）。
- **判定**：只有在 C2/C4 完成后、且 TTFT 被证明是瓶颈时才做。

## 七、C6 · Bounded-history replay（SWA bounded replay 类比）

- 论文：会话恢复时只重放最近 n_win 个 token，并把近似造成的依赖变化**在训练期模拟**（train-aware）。
- 本项目对应物：长历史会话在恢复或截断时，状态与「全程连续更新」不同；可以只回放最近 n 个 token 的状态更新，并**在训练期也随机模拟这种截断**，让模型对「状态被截断」鲁棒。
- **收益**：会话恢复成本 O(n) 而非 O(全长)；**验收**：截断长度扫描下的 BPB 曲线（应平坦）。

## 八、优先级与预算

| 序 | 项 | 成本 | 影响 | 依赖 |
|---|---|---|---|---|
| C1 | 优化器分工 | 1–2 天 + 一轮训练 | 收敛质量、优化器内存 −58 % | 无 |
| C2 | 会话状态持久化/降精度 | 2–3 天 | 体验（恢复即用）、存储 | 无 |
| C4 | 数据与验证器管线 | 持续 | **能力上限** | 无 |
| C3 | 深度旋钮 | 1 周 + 两轮训练 | 速度与质量同时受益 | **S4 层维复用** |
| C5 | 浅层 prefill | 1–2 周 | 仅 TTFT | C4、S2 |
| C6 | bounded-history replay | 1 周 + 一轮训练 | 恢复成本 | C2 |
