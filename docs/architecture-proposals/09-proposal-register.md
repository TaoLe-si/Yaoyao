## 二 · P 前置与基础设施

### P1 · 生产默认线程数 2 → 4
- **现状**：新池已就位，但默认仍是 2 线程（`set_cpu_threads` 默认走 legacy 路径）。
- **依据**：4 线程 844.8 ± 11.7 vs 冻结基线 760.2 ± 10.9 = **+11.1%**；8 线程无增益。
- **预期**：+11%。**成本**：改默认值 + 调用点，<1 小时。**数值**：bitwise（checksum 2901）。
- **依赖**：无。**否证**：4 线程 checksum ≠ 2901。

### P2 · 训练器优化器状态（12 B/参数）
- **现状**：每三值参数持 float32 master + moment + variance。已核实**不是**逐步 D2H（那是死代码）。
- **依据**：1.6 GB 表 ⇒ 优化器状态 12.8 GB。
- **预期**：优化器内存降到约 5 B/参数。**成本**：1–2 天。**依赖**：无（但这只在表规模下有实际意义，见 S7）。

### P3 · 断点续训路径（**已核实不存在**）
- **现状**：`src/train_noffn_fresh.cu:89` 是 `SortedGpuTrainer tr(initialize(Config{},20260911))`，argv[1] 只做存在性检查；
  `start=tr.steps` 恒为 0；日志行自报 `FRESH step=0`；`step_1512` 目录内无 Adam 动量/方差文件。
  `scripts/build_v01.bat` 构建的就是这个 exe。
- **后果**：**1512 → 2000 无法用现有代码完成**；任何"续训对照"（如 03 号文档的 A0）目前都跑不起来。
- **成本**：2–4 天（权重 + 优化器状态 + 步数 + 数据游标恢复，含身份校验）。**依赖**：无。

### P4 · 质量账
- **现状**：固定验证 NLL 有；**BPB、退化指标（n-gram 重复率/最长自重复/distinct-2,3/EOS 比例）、20 条固定探针、sealed 集全部待建**。
- **依据**：step1512 NLL 6.1065 但生成仍循环退化 → 单指标不可用。
- **成本**：1–2 天。**依赖**：无。**注意**：探针语料要独立于训练语料。

### P5 · 一键回归
- **现状**：S3 已产出可复用的 checksum 门 + 线程扫描；账本有 `dsb_ledger.mjs`；但三者未合成一条命令。
- **预期**：任何改动一条命令出「吞吐（3 位有效）+ checksum + 常驻字节 + 探针」四件套。
- **成本**：半天。

### P6 · 加载器上限与 mmap
- **现状**：`cpu_compact_bundle.hpp:6` DSB>512 MB 抛错、`:9` 元素>1e8 抛错。**对当前模型影响为 0**。
- **成本**：2 天。**依赖**：无（是 S7 的前置）。

## 三 · S 速度线

### S1 · 2-bit 打包常驻 + 内核内展开（`vpmultishiftqb` + `vpermb`）
- **现状**：`src` 内**无任何** packed-2bit / `vpermb` / `vpmultishiftqb` 代码。命名陷阱：`greedy_pipeline_grouped_model.hpp:19-21` 的 `packed` 指**已展开的 int8 行**。
- **做**：常驻 22.11 → **5.80 MB**（−74%）；沿用 16 列分组与 lane 折叠，保持 **bitwise**。
- **预期（修订）**：天花板 = min(带宽墙/字节, uop 上限/MAC)。带宽口径 18.68e9/5.80e6 = **3221 tps**；
  但每 token MAC 不变而字节降 3.8×，算力需求变成 **70 G MAC/s**（当前 18.4）→ 很可能转为 uop 受限，**实际落点 1700–3200**。
  且 5.80 MB < 16 MB L3，墙本身会上移。
- **成本**：3–5 天。**数值**：bitwise。**否证**：checksum ≠ 2901，或常驻降不到 ≈5.8 MB。

### S4 · 层维复用（R1 / R2 / R3 / R4）
- **现状**：未开工。档位：R1 输入投影 / R2 +递归 / R3 +读出 / R4 组内复用 m 候选。
- **预期（修订）**：
  - S4 单独（int8 布局）R3 → 唯一 **11.73 MB**：按 DRAM 墙 1593 tps，按头的 L3 速率 2360 tps。
  - **S1 + S4（打包）R3 → 约 3.0 MB**：6227（DRAM 墙）～9220（L3 速率）tps。
  - **原文档"8000–15000"只在叠加 S1 后成立**，且上限取决于墙是否真的搬到 L3。
- **成本**：先做**零训练代理实验**（离线把 Reuse 层权重替换成组内 Full 层）2–3 天；正式版 1–2 周 + 重训。
- **数值**：新算子（`dual-state-4-...`）。**依赖**：S1（才进 8000+ 区间）。**否证**：代理实验 tps 进不了 8000+。

### S5 · 候选池词表头
- **现状**：未开工。头占 38.6% MAC / 37.3% 字节，是最大单项。
- **做**：零训练先出「覆盖率 vs 头部流式字节」曲线。**判据**：质量无损需覆盖率 ≥99.9%；否则必须训练期同域（I4），成本翻倍。
- **成本**：诊断 1–2 天；正式 2–3 天 + 重训。**注意**：`greedy_head_observe` 全词表路径不得删除。

### S6 · int8 激活 + `vpdpbusd`
- **现状**：未开工。**S3 判定 H-BW 成立 → 本项降级**（不是 uop 受限）。
- **保留条件**：S1 若如预期转为 uop 受限，本项应重新提上来作为 S1 的后续。
- **成本**：误差界 1–2 天；正式 1–2 周 + QAT。**数值**：变（新算子 + 激活 QAT）。

### S7 · Engram 记忆表
- **现状**：未开工。成本模型：每 token 约 128 B–1.5 KB，与表大小无关。
- **先做**：合成表微基准（有/无预取、4 KB vs 2 MB 大页）。**判据**：无预取应见 ≈2.4 µs/token（≈400 tps 上限）；有预取 <10% 占比。
- **依赖**：P6。**必查反例**：held-out n-gram 无增益（"背下语料"）。

### S8 · `s→m` 依赖错位
- **依据**：论文 §2.4.1 Single-Pass mHC 同手法，原文称 *negligible performance degradation*，但**预训练仍保留多趟**。
- **做**：m 分支改读 `s_{t−1}`，s 段与 m 段合成一遍遍历。**预期** 5–15%。**成本**：改 config + CPU/CUDA 双路径。
- **数值**：非 bitwise → 误差界 + 新算子。**否证**：分解计时看不到合并收益（<5%）。

### S9 · 工作集分区 / L3 驻留（**S3 实测催生的新项**）
- **依据**：头 27.67 G MAC/s（embedding 8.39 MB 单独可进 L3） vs m 更新组 18.07 G MAC/s（层 13.37 MB 加进来共 21.76 MB > 16 MB L3）。
- **做**：研究把层工作集压到 16 MB 以下（与 S4 协同），或显式做 embedding 的 L3 驻留/非临时访问分离。
- **成本**：先做诊断（用现有插桩基准分相位测带宽）1 天。**依赖**：无。

### S10 · 行池完整版：物理核亲和性与阈值策略
- **现状**：池已实现，但**未做亲和性绑定**，阈值仍是固定 262,144。
- **依据**：S3 显示 4 线程即饱和，亲和性对 8 核以下的收益需要实测确认。
- **成本**：1 天。
