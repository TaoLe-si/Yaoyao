# 度量、评测与实验纪律（含本轮实测方法论）

> 本文件是「怎么知道我们真的变快了 / 变好了」的口径与流程。它不是附加项：本轮已经有三个结论因为口径错误被推翻（「整模型常驻 L3」「uop 瓶颈」「稀疏存储有收益」），**度量方法是这类项目里最容易被低估的基础设施**。

---

## 一、度量口径（先定义，再测量）

| 口径 | 定义 | 用途 | 本项目数值 |
|---|---|---|---|
| **DSB 打包口径** | 磁盘/传输字节：2 bit/权重 + 每行 float32 α | 加载时间、分发体积 | 5,798,167 B |
| **常驻口径** | 运行时 RAM：int8 展开（1 B/权重）+ 行尺度 + 浮点 | **内存与带宽结论** | 22,112,256 B |
| **每 token 权重字节** | 常驻口径下每 token 被读取的字节 | 带宽推算、token/s 天花板 | 22.1 MB（现状） |
| **MAC/token** | 稠密乘加次数 | 算力推算、头/层占比 | 21,757,952 |
| **单会话 token/s** | 单序列贪心解码，冷启动后取均值 | 速度验收主指标 | 680.8 |
| **首 token 延迟** | 从调用到第一个 token | TTFT（与吞吐分开报告） | 约 1.2–1.7 ms（空 prompt） |

**禁止混淆**：跨口径比较、把 DSB 字节当带宽、把 TTFT 当吞吐、把「2 线程」结果当「全核」结果。

## 二、每轮实验必备的三本账

### 2.1 模型账（静态，由工具产出）

`node docs/architecture-proposals/tools/dsb_ledger.mjs <ckpt>/final.dsb`

必含：operator id、校验和状态、参数量、DSB 字节、**常驻字节**、每 token 权重字节、MAC（头占比 / 每层小计 / 层内分解）、零元素比例与逐行密度、α 分布、每会话状态字节。

### 2.2 运行时账（动态，由基准程序产出）

| 指标 | 现状值（基线） | 获取方式 |
|---|---|---|
| token/s（正常回复） | 680.8 | `build/benchmark_noffn_decode.exe <ckpt>` |
| token/s（强制贪心 512 步） | 572–681 | 同上（FORCED 段） |
| 加载耗时 | 0.105 s | 同上 |
| 首 token 延迟 | 1.2–1.7 ms | 同上 |
| **分解计时**（norm / s / m / read / head） | **已建成**（S3 产出） | `build/benchmark_noffn_s3.exe <dsb> <threads> [mincost]` |
| 线程数 / 亲和性 | 1/2/4/6/8/16 可切；**亲和性仍未绑定** | 命令行参数（已加）；亲和性见登记册 S10 |
| 有效带宽估算 | 约 15.0 GB/s | 常驻字节 × token/s |

### 2.3 质量账（每次架构改动必给）

| 指标 | 现状 | 说明 |
|---|---|---|
| 固定验证集 NLL | 6.1065 @ step1512 | `METRIC nll` 日志行 |
| **BPB**（bits per byte） | **待建** | 论文用 BPB 而不是 NLL：把总 NLL(nats)/ln2 除以**目标文本字节数**，跨 tokenizer 可比 |
| 退化指标 | **待建** | n-gram 重复率、最长自重复长度、distinct-2/3、平均条件熵、EOS 比例 |
| 固定对话探针 | 手工观察 | 建议固化成 20 条 prompt 集合，改动前后逐条 diff |
| sealed test | 已开封集作废 | 新方案**新建**封存集；开封即视为 burned |
| held-out n-gram | 用于 Engram（见 04 号文档） | 训练集未出现过的 n-gram 子集 |

**为什么必须加 BPB 与退化指标**：当前模型「NLL 6.1065 但生成退化循环」，说明单看 NLL 无法判断可用性；论文 40.2 节用 BPB 也是为了跨 tokenizer/跨版本可比。

## 三、实验纪律

1. **一轮一个变量**：一轮 2000 步 ≈6.7 小时（≈300 更新/小时）。任何两个变量同时改 = 结论作废。
2. **先 dry-run**：续训/新配置先用小步数跑通（例如 20 步）确认身份串、日志路径、输出目录规则，再放量。
3. **身份留档**：每次运行记录 operator id、父检查点、父校验和、输出目录、`continue.verified.identity`；检查点目录**永不覆盖**。
4. **STOP 文件纪律**：`build/STOP_NOFFN` 是优雅暂停，`build/STOP_TRAINING` 是硬不变量；任何自动脚本都不得删除后者。
5. **对照必须同 seed/同数据顺序**：数据顺序固定，否则 6.7 小时的对照会被噪声吞掉。
6. **失败也要留档**：失败配置进本目录的消融日志（一句话 + 数字），避免重复踩坑。

## 四、本轮实测方法论（可复现）

### 4.1 论文文本抽取

- 工具：`tools/extract_pdf.py`（pypdf，无它时 `python -m pip install pypdf`）；
- **陷阱**：Python 文本模式写文件会把 `\n` 变成 CRLF，按 `\n\n===== PAGE BREAK =====\n\n` 切分会得到 1 页；正确切分用正则 `/\r?\n\r?\n===== PAGE BREAK =====\r?\n\r?\n/`。

### 4.2 DSB 解析（字节级账本）

- 布局：`DSB2` + manifest 长度(u64) + payload 长度(u64) + FNV-1a 校验和(u64) + manifest 文本 + `DSM1` 载荷；
- manifest：第 1 行 operator id，第 2 行 tokenizer SHA256，之后每行 `name rows cols ternary`；
- 载荷：6 个 u32 维度（layers/d/s/m/e/vocab）+ 逐张量（三值：每行 float32 α 后跟 cols 个 2-bit 码；非三值：连续 float32）；
- 2-bit 码含义：0 → 0，1 → +1，2 → −1，**3 非法**（解析器必须报错，这是格式不变量）。

### 4.3 CPUID（决定内核可用指令）

`tools/cpuid_probe.cpp`：leaf 0x7 子叶 0 的 EBX/ECX 位；本机结果 AVX512F/DQ/BW/VL/IFMA/BF16/VBMI/VBMI2/VNNI/BITALG/VPOPCNTDQ 全为 1，L2 1 MB/核、L3 16 MB。

> **编译陷阱**：`cl /Fo"dir\"` 会把结尾反斜杠当成转义引号，导致「缺少源文件名」；必须写成 `/Fo"dir\name.obj"`。

### 4.4 解码基准

    build\benchmark_noffn_decode.exe build\noffn_fresh\step_1512\final.dsb

输出解读：`LOAD seconds=…`（加载）、`NORMAL_DETAIL … decode_steps=… decode_seconds=… tps=…`（正常回复，主指标）、`FORCED` 多轮（强制贪心，检查稳定性）、`first_prediction_ms`（首 token）、`checksum`（贪心结果的确定性指纹——**改内核后必须一致**，这是数值一致性的第一道验收）。

### 4.5 训练监控与续训

- 日志：`build/noffn_fresh.log`（路径硬编码），逐行 `METRIC … nll=…`；
- 续训：**【已核实：不存在，旧文写法无效】** `build\yaoyao_train_v01.exe` 由 `src/train_noffn_fresh.cu` 构建，该文件第 89 行是
  `SortedGpuTrainer tr(initialize(Config{},20260911))`——**从零初始化**；argv[1]（SOURCE_CKPT_DIR）只做 `disk::directory()` 存在性检查与 `!= out` 判定；
  `start=tr.steps` 恒为 0，日志自报 `FRESH step=0`。且 `build/noffn_fresh/step_1512/` 内**没有 Adam 动量/方差文件**。
  → 旧文那条命令会**从头训练 <updates> 步**，不是续训。**1512 → 2000 需要先实现恢复路径（登记册 P3）。**

## 五、常见陷阱清单

| 陷阱 | 后果 | 正确做法 |
|---|---|---|
| 用 DSB 字节做内存/带宽结论 | 低估 3.8×，得出「常驻 L3」的错误结论 | 一律用常驻口径 |
| 把 2 线程结果当全核能力 | 低估可达吞吐 3–5× | 报告线程数与亲和性 |
| 单次测量当结论 | 抖动可达 ±15 % | 至少 3 次取均值 + 报极差 |
| 用训练 NLL 判断质量 | 训练 NLL 6.1 的模型会循环退化 | 训练 NLL + 固定验证 NLL + BPB + 退化指标 + 探针 |
| 把 probe 小语料结论外推 | probe step50 能答对，生产 5.95 M token 不能 | 明确标注语料规模 |
| 覆盖检查点目录 / 删 STOP_TRAINING | 违反不变量，实验不可复现 | 目录唯一化；STOP_TRAINING 常驻 |
| 改内核后只看吞吐 | 数值悄悄变化 | 先比 `checksum` 与 bitwise 一致性，再比吞吐 |
| 忽略加载/首 token | 用户体感差 | 三个数一起报：TTFT、吞吐、常驻字节 |

## 六、铁律（违反即停手）

> 以下每条都由**本项目的真实事故**换来，不是通则抄写。每条附事故出处。

### R1 · 禁止空转循环：同一段文字不得重复输出

**事故**：2026-09-11，在诊断模型「退化性重复」的过程中，**agent 自己在一次回复里
把同一段占位文本连发数十次直到耗尽输出预算**——正是它当时正在诊断的那个病。

**规则**：
- 一旦发现要写的内容与刚写过的重复，**立即停止生成**，改为执行工具调用或直接汇报。
- **禁止**用「思考过程」充当进展。每段思考必须**以一次工具调用或一次结论收尾**。
- 需要多步时用 `todo_write` 记录步骤，靠**工具结果**推进，不靠复述。
- 长任务用**后台作业**，不靠轮询刷屏；禁止无意义的长时等待。

**自检**：若连续两次工具调用之间没有产生**新信息**，即为空转，必须换手段或上报。

### R2 · 「开关无效」的结论，必须先证明开关真的生效

**事故**（三次同类）：
1. `TAO_LAYER_LIMIT` 从未被读取 → 层数扫描四次测的是同一配置；
2. `TAO_HEAD_LIMIT` 同样没接上；
3. 比较 `TAO_LAYER_SHARE=0,0` vs `0,1` 时输出**逐字节相同**，差点判定「层共享无影响」——
   换一组输入后差异立刻出现，**逐字节相同只是巧合**。

**规则**：任何「A/B 无差异」的结论，必须先给出 A 与 B 确实不同的证据：
`config_dump` 的字段变化、`checksum` 变化、或一条能区分两者的输入。

### R3 · 特性组合必须进回归矩阵（`#ifdef` 分叉的 schema 尤其危险）

**事故**：`fuse_sm`（层内 dispatch 融合）硬编码了 `m.candidate.*` / `m.gate.*` 六个张量名，
而 `TAO_DELTA_MEM` 的 schema 用 `mem.key/query/value` 取代了它们 →
**默认路径直接崩溃**（`invalid map<K, T> key`）。两个特性各自都测过，组合起来从未跑过。详见 doc 15。

**规则**：凡 `#ifdef` 分叉出的张量集合，**所有依赖具体张量名的代码路径必须带同样的 `#ifdef`**。
新增或修改任一特性后，**必须跑一遍与其他特性的交叉组合**。

### R4 · 训练与推理必须同算子（不变量 I4）

**事故**：`fuse_sm_` 默认开启，推理期让 m 分支读**更新前**的 `s_old`；
而训练器 `dual_state_autograd.cuh` 先算 `s[l]`、再让 m 读**更新后**的 `s[l]`，
且训练器**根本没有融合路径**。旧注释「训练期同域」是错的。

**规则**：推理侧每一个数值改写，都必须在训练侧找到对应实现；找不到就是违反 I4。
默认值必须是**与训练一致**的那个。已修：`fuse_sm_` 默认改为 `false`。

### R5 · 被证伪的特性要删掉或默认关闭，不留「可开关的错」

`fuse_sm` 的收益早已实测为 **0.991×**（无加速），却因默认开启而持续污染结果。
**规则**：收益被证伪 → 默认关；同时违反 I4 → 直接删。
保留开关的唯一理由是「还需要用它做 A/B 复现」。

### R6 · 评测必须用**分布内 held-out**，否则测到的是记忆

**事故**：doc 12 用 probe3 的 **30 词封闭名字集**测出「绑定 10/18」，
据此判定「数据问题、不是架构问题」。把名字集放大到 **3 787 个**后，
真实的组合绑定能力暴露为 **0/12**——**之前测的是查找表**。
同理，L2 上那个漂亮的「15/18」，用的名字正在语料内。

**规则**：
- 测试项必须**逐条核验不出现在训练语料中**（脚本化，不靠人工）；
- 名字/实体类任务必须**放大实体集**再测，小封闭集上的高分一律可疑；
- 报告任何「能力」数字时，必须同时给出**随机对照水平**。
  （H2R 的颜色 LCS = 0.00 **低于**对照 0.17，这个信号比「0/12」本身更有信息量。）

### R7 · 编译前先杀占用进程

**事故**：直接重编时 `h2r_cpu.exe` 被上一轮进程占用，写入静默失败，
随后浪费多轮排查「为什么新二进制行为没变」。

**规则**：重编前先 `taskkill` 目标 exe 与 `cl.exe`/`link.exe`/`nvcc.exe`；
编译后**用产物 mtime 变化确认真的重编了**，不能只看退出码。

### R8 · 训练/推理规模不匹配时，结论必须标注保留

**事故**：L4 @400（NLL 0.30）与 L2 @200（NLL 0.09）并未 NLL 匹配，
「绑定没改善」因此带有「可能还没训够」的保留。
**而复制结论不受影响**——纯复制模型训到 NLL 0.11，在语料外仍是 0/5。

**规则**：跨规模比较必须**在匹配的训练水平上**做；做不到就在结论里显式写出保留，
并区分「受此保留影响」与「不受影响」的子结论。
