# 26 · 三个学习能力缺陷的受控实验与根因判定

> 本文取代 doc 25 的"延迟线修复"提议。doc 25 的根因分析（第 0 层记忆键/值同源）
> 在数学上成立，但其工程方案（延迟线）经受控 A/B **被实测否决**，已完全回退。
> 本文记录三个缺陷各自的「受控实验 → 根因 → 修复 → 复验」。

## 零、结论速览

| 缺陷 | 受控实验 | 根因 | 状态 |
|---|---|---|---|
| 1 退化复读 | 同模型、同步数、仅激活不同 | **训练/推理激活不一致（R4）** | ✅ 已修复并复验；语料外仍有残留（doc 28） |
| 2 算术弱 | 纯算术语料 vs 混合语料 | **数据配比**（4.27%）**＋ 数字被切成不透明单 token** | ✅ 根因已判定（doc 28 §三） |
| 3 有序复制 | 混合语料 vs 纯复制语料 | 顺序 = **数据配比**；终止 = **无计数通道** | ⚠️ 顺序可解；终止待解 |
| 3 原样复制 | 语料内外对比 | **语料只有 15 个唯一句 ×40 重复** | ✅ 根因已判定（doc 28 §二） |

**关键纠正**：初稿曾判定「L≥4 有序复制是架构天花板」——**该结论已被推翻**，
那是单一任务小语料 **26.5 个 epoch 的过拟合伪影**（详见 §3.4）。
在混合语料上同一任务顺序前缀达 **24/40、L5 为 4/5**。

**目前唯一确认的架构性缺陷是「计数/终止」**：模型能把 5 项全部按序吐对，
然后多吐 1–2 项才停（§3.5，加终止符的受控 A/B 已否证"缺停止线索"这一解释）。

## 一、缺陷 1：退化复读

### 1.1 现象（旧模型 `h2r_l6_long/step_500`）

```
U 请按顺序输出：铅笔、草莓、桃子。不要添加其他文字。
A 铅笔、草莓、草莓、桃子、草莓、草莓、草莓、草莓、铅笔、草莓      ← 退化复读

U 我叫什么名字？
A 你喜欢喜欢喜欢喜欢喜欢喜欢喜欢喜欢喜欢…（60+ 次）              ← 退化复读
```

### 1.2 根因：R4 违规（训练/推理算子不一致）

| 侧 | 激活函数 | 最大偏差 |
|---|---|---|
| 训练器 `ds_update` | 精确 `expf` / `tanhf` | — |
| 解码器 `applyDefaultArch()` | Padé 快速近似（`fast_act_=true`） | **2.352e-02**（tanh） |

`act_parity_test.exe` 实测：旧精确 vs 快速 tanh **2.352e-02**、sigmoid **1.592e-01**。

即：训练出的状态轨迹与推理时走的轨迹不是同一条。状态是**逐步累积**的，
每步 1e-2 量级的偏差在几十步后把状态推离训练流形，落入自激固定点 → 复读。

### 1.3 修复

按用户决策（解码器 Padé 对 CPU 友好），**把训练器统一到 Padé**，而不是回退解码器：

- `dual_state_cuda_resident.cuh`：新增 `ds_fast_tanh/_grad`、`ds_fast_sigmoid/_grad`，
  以及 `ds_act_*` 包装，`TAO_TRAIN_FAST_ACT` 默认开启（`-DTAO_TRAIN_EXACT_ACT` 可回退）
- `dual_state_cuda_backward.cuh`：反向同步改用 `ds_act_*`
- `gpu_fixed_validation_arch2.cuh`：`state_update` 同步
- **`ds_sigmoid` 本身刻意不改**：`mem.beta` 与 silu 必须与 CPU 解码器保持精确一致

`act_parity_test.exe` 复验：**2.352e-02 → 1.192e-07**（= 1 ULP，改善 197,000 倍），`PARITY_OK`。

### 1.4 复验（同语料 `noffn_l6`、同步数、仅激活不同）

| 输入 | 旧（精确激活） | 新（Padé 统一） |
|---|---|---|
| `请按顺序输出：铅笔、草莓、桃子。…` | `铅笔、草莓、草莓、桃子、草莓、草莓、草莓、草莓、铅笔、草莓` | **`铅笔、草莓、桃子`** ✅ |
| 只问名字（12 held-out） | 名 9/12（**含复读**） | **名 11/12，无复读** ✅ |
| 两问合一 | 名 11 / 色 11 / 两 10 | 名 11 / 色 12 / 两 **11** ✅ |

**结论：退化复读是训练/推理不一致造成的，已修复。** 且 Padé 版全面优于精确版。

## 二、缺陷 2：算术能力弱

### 2.1 现象（混合语料 `noffn_l6`）

| 组 | `+` | `×` |
|---|---|---|
| 语料内（见过的 320 数对） | **1/15** | **0/15** |
| 组合泛化（未见数对） | 1/15 | 0/15 |
| 外推 21..40 | 0/12 | 0/12 |

失败模式：输出恒为少数常量（`11`/`20`/`14`/`15`/`2`）——**边缘分布坍缩**。

### 2.2 数据配比盘点（`noffn_l6`，33120 个用户话轮，**修正分类**）

| 任务 | 话轮数 | 占比 | 唯一问句 | 唯一答句 | 平均重复 |
|---|---:|---:|---:|---:|---:|
| 绑定 | 25471 | **76.91%** | 8248 | 10444 | 3.1× |
| 有序复制 | 3000 | **9.06%** | 2970 | 2915 | 1.0× |
| 其他 | 2635 | 7.96% | 359 | 70 | 7.3× |
| 算术 | 1414 | **4.27%** | 641 | **153** | 2.2× |
| 原样复制 | 600 | **1.81%** | **15** | **15** | **40.0×** |

> 分类修正说明：初稿把 `按顺序复述：` / `请依次说出：` 归入"其他"，
> 实际它们与 `请按顺序输出：` 同属有序复制，合计 **3000** 篇（9.06%），不是 1000 篇。
> 详细的数据/ tokenizer 缺陷见 doc 28。

### 2.3 受控实验：纯算术语料

`scripts/gen_corpus_arith_pure.mjs` → `data/arith_pure`：
6400 篇**纯算术**（a,b ∈ 1..20 的 400 数对中只用 320，留 80 作组合泛化），
四种问法，无任何对话/绑定任务。600 步，训练 **NLL 0.015347**。

| 组 | `+` | `×` |
|---|---|---|
| **语料内** | **14/15** ✅ | **14/15** ✅ |
| 组合泛化 | 0/15 | 6/15 |
| 外推 21..40 | 0/12 | 0/12 |

### 2.4 判定

- **根因 = 数据配比。** 架构完全能承载算术（语料内 14/15）；混合语料下 4.03% 的份额
  被 77% 的绑定任务淹没，模型只学到边缘分布。
- **附带发现（重要）**：组合泛化 `+` 0/15、`×` 6/15 ⇒ 模型学到的是**查表**，不是算法。
  真正习得算术需要远超当前规模的语料与步数，不能靠调架构解决。

## 三、缺陷 3：语料外复制失败

### 3.1 现象

- 原样复制（语料外）**0/5**
- `请按顺序输出：钟表、尺子、上海。…` → `钟表、尺子`（截断）

### 3.2 关键证据：连训练样本都做不对

`桃子、草莓、桌子、绿色、钟表、鱼`（6 项）**就在 `noffn_l6` 训练语料内**，模型输出：

```
桌子、草莓、桌子、桌子、桌子        ← 5 项，顺序错，项数错
```

有序复制在语料中为 3000/33120 = **9.06%**（`请按顺序输出` / `按顺序复述` / `请依次说出` 三种问法合计），
算术 4.27%，原样复制 1.81% —— 三者都被 76.91% 的绑定任务淹没。

### 3.3 受控实验：纯有序复制语料

`data/copy_order`（6000 篇，长度 1..8，纯"有序复制"单一任务），40 条同口径测试：

| 架构 / 步数 | 完全正确 | 顺序前缀全对 | 集合正确 |
|---|---:|---:|---:|
| 无延迟线（300 步） | 9/40 | 10/40 | 24/40 |
| 延迟线（300 步） | 12/40 | 15/40 | 17/40 |
| 延迟线（400 步） | 9/40 | 17/40 | 19/40 |

### 3.4 ❌ 曾被误判为「架构天花板」，实为**过拟合伪影**

在纯复制语料上训到 1200 步（`build/copy_ceil`），长度 ≥4 的完全正确率恒为 0/5。
本文初稿据此判定「L≥4 是架构上限」。**该结论已被后续实验推翻。**

**反证**：在**混合**语料（`build/rebal`，31920 篇）上训 900 步，同一个有序复制任务：

| 长度 | 完全 | 顺序前缀全对 | 顺序对但超量 |
|---|---:|---:|---:|
| 3 | 2/5 | 4 | 2 |
| 4 | 1/5 | 4 | 3 |
| **5** | 0/5 | **4** | 4 |
| 6 | 0/5 | 2 | 2 |
| **合计** | **13/40** | **24** | **12** |

**混合模型（顺序前缀 24/40、L5 达 4/5）远好于纯复制模型（11/40、L≥4 全 0）。**

**原因：过拟合。** `copy_order` 只有 6000 篇、唯一提问仅 **1971/6000 = 32.9%**，
训 1200 步 ≈ **26.5 个 epoch** ⇒ 模型记住了训练集并坍缩到退化解
（前 2 项正确、第 3 项起退化为该位置的高频边缘分布）。
而 `rebalanced` 是 31920 篇 / 900 步 ≈ **4.2 个 epoch**，泛化正常。

> **教训**：单一任务小语料上"训得越久越差"是过拟合，**不能据此推断架构上限**。
> 判定架构上限必须在**混合语料**上做，或至少控制在少量 epoch。

### 3.5 判定（第二次修正）

| 成分 | 现象 | 根因 | 状态 |
|---|---|---|---|
| 有序检索（L≤5） | 顺序前缀 4/5 | 数据配比（有序复制仅 9.06%） | ✅ 配比可解 |
| **终止/计数** | 顺序**全对**却多吐 1–2 项 | 无计数器；矩阵记忆不承载项数 | ❌ **仍未解决** |
| 原样复制（语料外） | 0/5 | 语料只有 **15 个唯一句 ×40 重复** | ✅ 见 doc 28 |

**终止缺陷的实测形态**（`build/rebal_term` step_900，答案带终止符）：

```
期望="成都、草莓、杭州、紫色、黄色"
模型="成都、草莓、杭州、紫色、黄色、杭州。"     ← 5 项全对 + 多 1 项
期望="香蕉、白色、桃子、鱼、黄色"
模型="香蕉、白色、桃子、鱼、黄色、香蕉。"     ← 5 项全对 + 多 1 项
```

### 3.6 终止符受控 A/B：**否证**

假设：答案末尾缺 `。`，模型只能靠"数数"停下 ⇒ 加终止符即可修复。

`data/rebalanced_term` 与 `data/rebalanced` **唯一差别**是有序复制答案末尾加 `。`
（+6000 token，其余逐字相同）；同样 900 步：

| 指标 | 对照 `rebal` | 终止符 `rebal_term` | 结论 |
|---|---:|---:|---|
| 完全 | 13/40 | 12/40 | ≈ |
| 顺序前缀全对 | 24 | 23 | ≈ |
| **顺序对但超量** | 12 | **17** | **变差** |
| 集合 | 25 | 31 | 好 |
| 训练 NLL | 0.1615 | 0.1522 | — |

**加终止符没有减少超量，反而增加了**（模型把 `。` 放在多吐的那一项之后）。
⇒ 终止缺陷**不是"缺停止线索"**，而是**模型不知道列表在哪里结束**（无计数能力）。

### 3.7 方法学核验（已排除的假象）

| 可能的假象 | 核验 | 结论 |
|---|---|---|
| 语料里没有 L≥4 样本 | `gen_corpus_copy_order.mjs:24` `L = 1+floor(rnd()*8)`，每长度约 750 篇 | ✅ 有 |
| 解码器截断长输出 | `decode_diag.cpp:38` `max_tokens = 64`；中文近字级（8 项 ≈ 27 token） | ✅ 不截断 |
| 评测解析错误 | `eval_copy_order.mjs:47` 按 `、` 切分并剥 `。`；L1/L2 全过 | ✅ 正常 |

**剩余架构问题**：计数/终止通道。代价分析见 doc 27 §四。

## 四、延迟线：doc 25 的方案被实测否决（已完全回退）

### 4.1 数学根因（成立）

第 0 层 `xn = norm(emb(token)·√d)`，故 `mem.key` / `mem.query` / `mem.value` 的输入
**是同一个 token 的函数**。写入 `(k(t_i), v(t_i))`、读出用 `q(t_i)`，
矩阵记忆在数学上只能是**集合**，不可能承载顺序。

### 4.2 受控 A/B（同语料 `noffn_l6`、同步数 600、仅架构不同）

| 架构 | 两问合一 名/色/两 | 变体 名/两 | 只问名 | 复读 |
|---|---|---|---|---|
| 旧 精确激活 | 11 / 11 / 10 | 12 / 11 | 9（含复读） | 有 |
| **Padé 无延迟线** | **11 / 12 / 11** | 11 / 11 | **11（无复读）** | **无** |
| Padé 仅第 0 层延迟线 | **0** / 12 / **0** | 12 / 12 | 12 | 无 |
| Padé 全层延迟线 | **0** / 11 / **0** | 5 / 5 | 8 | 无 |

### 4.3 机制与结论

延迟线给模型一条**近因捷径**：`我叫什么名字？喜欢什么？` 以 `喜欢什么？` 结尾，
模型于是只回答第二个子问题（输出 `紫色。`），而不再整合整段绑定话轮。
**代价（绑定 11/12 → 0/12）远大于收益（纯复制顺序 10 → 17/40）。**

### 4.4 回退与验证

- 全部改动已从 `dual_state_config.hpp`、`dual_state_cpu.hpp`、
  `greedy_pipeline_grouped_model.hpp`、`batch_train_graph.cuh`、
  `dual_state_initialization.hpp`、`dual_model_bundle.hpp` 移除；
  源码全文检索 `TAO_DELAY` / `prev_tok` / `prev_x` / `mem.*.prev` / `prev.norm` **零残留**。
- schema 恢复 5 个 `mem.*` 张量，算子 ID 恢复 `dual-state-4-noffn-delta-mem-input-sqrt-d`。
- **逐位回归**：`train_delta_long` 2 步 NLL = `15.829307` / `15.700040`，与改动前**完全一致**。

## 五、硬约束：不得拖累 CPU 解码速度

用户明确要求：**所有改动不能拖累 CPU 解码速度**。

本次回退把延迟线彻底删除（而非留编译开关），因此：

- `LayerState` 布局恢复为 `{Vec s,m;}`（无额外 4 字节/层）
- `recurrent()` 热路径恢复逐条指令相同（去掉了每 token 一次的 `state` 遍历写 `prev_tok`）
- schema 恢复原状，无额外张量查表
- 验证方式：同一模型（`h2r_l6_long/step_500`）、同一 600 条提示、
  改动前 `h2r_cpu_base.exe` vs 回退后 `h2r_cpu_rev.exe`，交替三次取中位

### 实测结果（`build/decode_speed.txt`）

| 版本 | 三次耗时 | 中位 | 生成 token | 回复数 |
|---|---|---:|---:|---:|
| 改动前 `h2r_cpu_base.exe` | 15.70 / 16.49 / 16.28 s | 16.284 s | 10927 | 600 |
| 回退后 `h2r_cpu_rev.exe` | 15.78 / 16.09 / 15.84 s | **15.841 s** | 10927 | 600 |

- **中位耗时比 = 0.9728** ⇒ 无退化（落在噪声带内，甚至略快）
- 生成 token 数完全相同（10927）⇒ **输出也逐字一致**

**结论：本次改动对 CPU 解码速度零影响，且输出不变。**

## 六、下一步（进入课程式长训的依据）

三个缺陷的根因都指向**同一件事：语料配比**。因此 doc 20 的课程式三段设计
不是可选优化，而是**必需的修复手段**：

| 阶段 | 内容 | 目的 |
|---|---|---|
| core | 算术 / 有序复制 / 原样复制 **各自单独**精训 | 让每项能力先"学得会"（纯算术语料已证 14/15） |
| mixed | 按目标配比混合 | 让多项能力共存而不互相淹没 |
| interfere | 加入干扰项 | 抗遗忘、抗混淆 |

**必须调整的配比**：当前混合语料里绑定 77% / 算术 4% / 复制 5%，
core 阶段需把后两者提到与绑定同量级。
