## 一、硬约束（不变量，任何建议都不得违反）

| # | 不变量 | 含义与来源 |
|---|---|---|
| I1 | **无 FFN，永不回归** | 夭夭 0.1 的身份就是「三值双状态、无升维/降维分支」。任何方案（含记忆模块）都不得重新引入 FFN、SwiGLU、MoE 专家层。 |
| I2 | **三值权重 + 每行尺度** | 权重为逐行最小二乘投影出的 $\{-1,0,+1\}$ 与行尺度 α；训练保存浮点 master，STE 反传。 |
| I3 | **固定状态，无 KV cache** | 每会话状态 O(L(s+m)) 且与序列长度无关；不引入随上下文增长的状态（除非作为「可选全局分支」单独论证）。 |
| I4 | **训练/推理同架构** | CPU、串行 CUDA、批处理 CUDA、固定 GPU 验证必须走同一算子定义；**任何推理期近似都必须在训练期原样模拟**（这条直接来自论文的 candidate pool / bounded replay / QAT 纪律）。 |
| I5 | **身份化产物，禁止静默复用** | 改动 schema 或算子即产生新 operator id / 新 DSB-SCP；禁止加载旧 checkpoint；检查点目录不可覆盖；`STOP_TRAINING` 常驻。 |

## 三、结论摘要

1. **瓶颈定位（S3 已判定为 H-BW，不再是推断）**：常驻 22.1 MB/token，4 线程实测 844.8 token/s = **18.68 GB/s**，且 `18.68e9 / 22.11e6 = 845` 与实测吻合到 3 位有效。判定依据：每线程 MAC 率随线程数**崩塌**（8.13 → 4.60 → 2.26 G MAC/s），4→8 线程 0.99×，16 线程更差，调低并行分发阈值无收益。详见 08 号文档。
2. **速度第一杠杆是「减字节」，不是「减指令」**：把常驻布局从 int8 改回 2-bit 打包、在内核内用 `vpermb`（AVX-512 VBMI）展开 → 22.1 MB → 5.8 MB/token，且**数值可与现网 bitwise 一致、无需重训**。
3. **第二杠杆是并行度**：当前只用 2/16 线程；行间独立、按整行切分 → bitwise 不变，2 → 8 线程。
4. **第三杠杆是层维复用（CSA2 唯一对本目标直接有效的机制）**：唯一 int8 权重 21.76 MB → 11.74 MB → **装进 16 MB L3**，把负载从 DRAM 墙搬到 L3 + 多核。
5. **第四杠杆是候选池词表头**：输出头占 38.6 % MAC、37.3 % 字节；两段式（簇 → 簇内精算）可把 8.39 M MAC 降到 ~0.5 M、头部流式字节降到 ~20 KB。
6. **Engram 正式纳入，但它是「能力与规模」杠杆而非「当前速度」杠杆**：每 token 只碰 O(阶数×头数) 个条目（≈1.5 KB），**与表大小无关**，因此参数量增长可以放在稀疏表里而不拖慢解码；前提是**确定性寻址 + 预取流水线 + 大页**（否则随机延迟会把上限压到 ~400 token/s）。
7. **实测否掉的两条路（省下大量时间）**：① 索引式稀疏存储（密度 ~54 %，2 bit/元素已是最优）；② Cauchy–Schwarz 精确剪枝（α 极窄，实测可剪枝 0 %）。→ 词表头只能走「近似 + 训练期对齐」。
8. **能力瓶颈不在架构而在数据/算力**：probe 小语料能答对、生产 5.95 M token 语料 + 2000 步不能。
   > 【边界】「论文第 5 章」说的是**后训练**收益几乎全来自数据与环境管线；把它外推到本项目的**预训练**只是类比，不是引用。见 10 号文档。
9. **基础设施事实（已按源码逐行更正）**：
   - 【更正】旧文称 `update()` 每步对每个张量做全量 `grad.host()` 回读、`project()` 全量 host 扫描——**在生产路径上不成立**。两条都以 `#ifdef TAO_GPU_HEALTH` 分叉，而 `train_yaoyao_graph_gpuval.cu:3` 定义了该宏，实际走 `GpuHealth` 的 GPU 侧归约，`finish()` 只回读 4 B + 8 B。逐元素 `host()` 分支是未编译的死代码。
   - **真正阻碍**：① 每参数 float32 master+moment+variance（**12 B/参数**）；② 加载器硬编码 1 亿元素与 512 MB 上限。
   - 【新】**断点续训路径不存在**：`train_noffn_fresh.cu:89` 是 `initialize(Config{},20260911)`（从零初始化），argv[1] 只做存在性检查，`start=tr.steps` 恒为 0，`step_1512` 目录内无 Adam 动量/方差文件。**1512 → 2000 目前跑不起来**，所有质量对照都卡在这里。
10. **纪律**：一轮训练只要 6.7 小时 → **一轮换一个变量**；每次改动必须同时给出「吞吐（3 位有效）＋ 数值一致性（bitwise 或误差界）＋ 生成质量回归（固定探针 + BPB）」。

## 八、纪律（对每条建议都生效）

1. **一变量一轮**：一轮训练 ≈6.7 小时，架构改动必须单独成轮，日志与 `identity` 串留档。
2. **三件套验收**：吞吐（3 位有效）＋ 数值一致性（bitwise 或明确误差界）＋ 生成质量回归（固定对话探针 + BPB）。缺一不合并。
3. **保留诊断路径**：现网的全词表贪心（`greedy_head_observe`，扫全部行 + 非有限值检测）既是回滚路径也是受限域头的一致率诊断工具，不得删除。
4. **封存集不可复用**：已开封的 sealed test 一律作废，新方案新建封存集。
5. **口径统一**：写内存/带宽结论时一律使用**常驻（int8 q）口径**，写磁盘/传输结论时使用 DSB 打包口径，并在表格标题中标注。
