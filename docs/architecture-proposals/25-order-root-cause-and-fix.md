# 25 · 根因证明：第 0 层记忆在数学上只能是「集合」，不可能承载顺序

> 本文给出 doc 22 实测现象（集合 57% / 完全 10%）的**严格数学解释**，
> 并据此确定唯一正确的架构修复方向。
> 先排除代码错误：状态重置是**正确的**（`batch_train_graph.cuh:13` 用 `restart`
> 同时重置 `s[l]` 与 `m[l]`），文档间不串味。

---

## 一、第 0 层记忆是恒等映射（证明）

`batch_train_graph.cuh` 的前向：

```cpp
auto x = tape.embedding_device(...);            // x = emb(token) * sqrt(d)
for(l = 0; l < layers; ++l) {
    auto xn = tape.norm_batch(x, p+"input.norm", slots);   // 关键
    auto kk = linear(p+"mem.key",   xn, dk, c.d);
    auto qq = linear(p+"mem.query", xn, dk, c.d);
    auto vv = linear(p+"mem.value", xn, dv, c.d);
    auto khat = tape.l2norm(kk, slots, dk);
    auto beta = tape.sigmoid(...);
    auto dm = tape.delta(m[l], khat, qq, vv, beta, slots, dv, dk);
    m[l] = tape.select_device(old_m, dm.first, mask, offset, slots);
    x = tape.add(x, tape.norm_batch(tape.add(linear(p+"read.s",s[l],c.d,c.s), dm.second), ...));
}
```

**第 0 层时 `x = emb(token)·√d`，所以 `xn_0` 是「当前 token 嵌入的归一化」。**

于是：

```
k_0 = W_k · xn_0 = f(当前 token)
q_0 = W_q · xn_0 = g(当前 token)
v_0 = W_v · xn_0 = h(当前 token)
```

**`k`、`q`、`v` 三者都是同一个 token 的函数。** 写入的是 `(k(t_i), v(t_i))`，读出用 `q(t_i)`。

### 推论

若序列中两个位置出现**同一个 token**，它们的键完全相同 ⇒ 后写覆盖先写。
因此第 0 层记忆能保存的信息只有：

> 「每个**不同** token 最近一次出现时的 value」

**这正是集合（set）的定义，不含任何位置信息。** 第 0 层记忆在数学上**不可能**承载顺序。

### 与实测的吻合

| 实测 | 解释 |
|---|---|
| 集合正确 17/30，完全正确 3/30 | 集合能存，顺序无处可存 ✓ |
| 长度 1 完美、长度 2 接近、长度 ≥3 崩溃 | 集合容量约 4 项（doc 22 实测），但**顺序通道容量为 0** ✓ |
| `黄色、橡皮、雨伞` → `黄色、雨伞、橡皮` | 三项都在集合里，顺序是任意的 ✓ |
| 重复惩罚完全无效 | 问题不是重复，是模型不知道下一个是哪个 ✓ |

## 二、第 1 层为什么也没救回来

第 1 层时 `x = emb(token) + norm(W_rs·s_0 + o_0)`，所以 `xn_1` **确实**含历史信息
（来自 `s_0` 与 `o_0`）。理论上第 1 层可以构造 bigram 表：
写入 `(item_i → item_{i+1})`，读出时用 `q` 匹配 `item_i`。

**但存在结构性障碍**：

1. **键被当前 token 主导。** `xn_1` 里 `emb(token_i)` 是直接加进去的大分量，
   而 `item_{i-1}` 只能通过 `s_0` 间接、衰减地体现。
   要写 bigram 需要 `k_1 = encode(item_i)`，但 `k_1` 天然更像 `encode(item_{i+1})`。
2. **`s` 是有界漏积分器。** `s ← s + σ(a)(tanh(u) − s)`，
   `tanh` 把候选值压到 (−1,1)，无法实现无损移位寄存器。
3. **一半记忆容量被浪费。** 第 0 层记忆是恒等映射，纯属浪费。

实测（6000 篇纯任务语料、800 步、完全持平）证明第 1 层不足以补偿。

---

## 三、唯一正确的修复方向：给记忆一条「上一个 token」直连通道

问题的本质是**键与值取自同一位置**，而 bigram 需要
**键取自位置 i−1、值取自位置 i**。

### 方案：延迟线（1-step delay）输入

把记忆投影的输入由 `xn_t` 改为拼接 `[xn_t ; xn_{t-1}]`：

```
mem.key    : dk × d  →  dk × 2d
mem.query  : dk × d  →  dk × 2d
mem.value  : m  × d  →  m  × 2d
mem.beta   : 1  × d  →  1  × 2d
```

于是第 0 层也能形成 bigram：

| 时刻 | 键（来自 `xn_{t-1}`） | 值（来自 `xn_t`） | 存入 M |
|---|---|---|---|
| prompt 位置 i | `item_{i-1}` | `item_i` | `(item_{i-1} → item_i)` ✓ |
| 生成步 j | 输入是 `item_{j-1}` | — | 用 `q(item_{j-1})` 读出 `item_j` ✓ |

**这是当前架构的严格超集**：把后一半权重学成 0 就退化为现状。
不需要新算子、不需要 FFN、不改变「双状态」设计。

### 代价

- 每层记忆参数约 2×（`mem.*` 由 328 k → 656 k），每层总量约 1.6×
- 需要在状态里携带 `xn_{t-1}`（d 维，与层无关，可只存一份）
- 算子 ID 必须变更：`dual-state-4-noffn-delta-mem-input-sqrt-d`
  → `dual-state-5-noffn-delta-mem-delay-input-sqrt-d`
- 旧检查点**不兼容**，必须重训（本来也要重训，见 doc 24）

### 不采用的方案

| 方案 | 为何不采用 |
|---|---|
| 加 FFN | 架构已明确移除，禁止回退 |
| 只加大 `s` | 治标；`tanh` 有界漏积分器的结构限制仍在（§二.2） |
| 显式位置编码 | 生成位置与输入位置不对齐，需额外学偏移；延迟线更直接 |
| 只加层数 | 实测 L4 对照（扫描中）；即便有用也没解决第 0 层恒等映射的浪费 |

## 五、剩余缺陷：终止 / 计数

延迟线修好了「顺序」，暴露出下一个独立缺陷：**模型不知道列表何时结束**，
固定多输出一项（`西安`/`尺子`/`猫`）后停止。

### 机制分析

答案格式是 `A item1、item2、…、itemN`，**N 之后没有任何内容线索**——
模型必须"数"出项数，而 `s ← s + σ(a)(tanh(u) − s)` 是有界漏积分器，无法可靠计数。

### 但线索其实存在

prompt 里 `itemN` 后面跟着 `。`（`请按顺序输出：…itemN。不要添加其他文字。`）。
延迟线使 bigram `(itemN → 。)` **确实被写进了 M**。
因此模型完全可以学到：「若链上下一项检索到 `。`，则输出 TURN_END」。

即：**终止信息是可得的，只是尚未学会**。候选做法：

| # | 做法 | 评价 |
|---|---|---|
| A | 继续训练更久 | 最省事，先试 |
| B | 答案末尾也带 `。`，给终止一个显式内容线索 | 改数据格式，但最直接 |
| C | 语料中加入「项数」显式表述 | 近似作弊，不优先 |
| D | 单独训练一个"结束"通道 | 过度设计 |

**优先 A，其次 B。**
