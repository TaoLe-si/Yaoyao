# 夭夭架构整理与集成边界

## 结论
当前有可复用组件，没有完整语言模型架构。进入“完善统一架构规格”阶段，不进入全量集成或正式训练。GPU原生C++/CUDA训练、CPU推理解码是固定执行模式。不得用CPU训练新基线替代。旧权重、源文件、实验记录保留。
能力对标现有语言模型，按能力/训练成本/CPU延迟/内存综合判断，不要求模型回答100%正确；数据对齐、因果性和算子实现仍需严格验证。禁止无意义重复测试。

## 必须补齐的统一计算图
建议主链：token -> embedding -> 多层因果状态块 -> 归一化/词表输出 -> next-token logits。
每层有独立持久状态，跨token更新；每条对话开始清零，分块训练保留前向状态并明确detach位置。不能把soft训练门直接替换为hard推理门而称作同一模型。

待定但必须一次定清：
1. 状态块方程：当前token如何影响候选、门和旧状态，维度与广播语义，归一化位置及数值范围。需要保留内容相关更新，不固定无条件衰减。
2. 临时非线性扩展是否属于主干；其输出是否写回持久状态，必须显式定义。
3. 局部关联是可选读出还是必需主干；若搜索历史候选，就必须计入历史缓冲、检索成本，不能宣称无历史缓存。首版不应同时加入尚未证明必要的检索分支。
4. 全词表输出头、层数/宽度/参数共享与tokenizer；261字节编码只是管线基线，非已定最终词表。
5. 三值矩阵范围、逐行尺度、偏置/归一化/状态精度、量化投影与STE定义；GPU训练所见有效权重必须与CPU导出权重一致。
6. 完整反向路径：跨时间梯度、分块截断、门梯度、输出损失归一化、优化器主权重/矩与断点恢复。不能只实现若干CUDA局部函数就称训练链完成。

## GPU训练到CPU解码接口
训练检查点：浮点主权重、有效三值投影规则/尺度、优化器状态、训练步数、RNG和数据顺序、tokenizer与模型配置版本。
推理模型：版本化结构配置、tokenizer指纹、逐张量形状/类型、2bit符号与FP32尺度、必要浮点参数、长度和校验；不携带优化器。
CPU加载可按性能选择展开计算或packed计算；三值权重约束与直接packed执行不是同一要求。解码按token更新同一状态方程，无训练时才有的额外标签，不读取未来token。
归一化、门函数、量化舍入和EOS必须同定义。CPU/CUDA可有浮点误差容限，不能要求所有浮点内部值逐位一致；离散行为差异须有监控。

## 集成门槛（不是100%能力门槛）
- 一份无歧义图规格及参数/状态/计算预算，能逐算子映射CPU与CUDA。
- GPU前向/反向与小规模数值参考正确，真实语料mask/reset一致。
- GPU一次有限训练能保存、恢复、导出，CPU能够加载同一权重生成文本。
- 固定真实语言验证集报告损失与任务能力、CPU延迟/内存；能力有误差可继续集成改进，不以清零错误为前提。
- 完整链连通后再扩大数据/模型、比较当前可运行LLM，禁止用符号全通过替代真实能力。
