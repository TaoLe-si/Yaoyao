# 第十六步已批准：交付接口与进入实现

训练checkpoint与推理模型分离。checkpoint含配置/tokenizer指纹、FP32主权重与浮点参数、AdamW矩和步数、LR计划、量化版本、数据位置/RNG、每槽双状态和会话位置；仅完整优化器步骤边界保存。恢复从主权重重新投影。

推理模型含结构/算子版本/tokenizer指纹、张量目录/形状、2bit符号、逐行FP32尺度、浮点偏置和归一化增益、长度与校验。不含优化器。CPU允许展开有效权重，不更改尺度或使用主权重。

核心step(token_id,session_state)->logits且更新状态，恰好消费一个token。权重共享，各会话状态独立。tokenizer/采样/显示在核心之外。TURN_END消费后停止，不重复消费。

用户批准进入实现，不再增加架构分支或要求逐项审批。已有架构是实现基线，不等于已经验证能力/性能。工程数值细节必须明确并归档，若改变已批准模型语义另行说明，不静默修改。

实施次序：统一规格与张量目录->共享CPU参考和CUDA同图前向/反向->训练checkpoint/推理导出->正式tokenizer与数据接入->一次完整GPU有限训练/恢复/CPU生成验收。CPU参考用于推理和小规模梯度核对，不进行CPU模型训练。已有真实数据reader和Arrow读取复用，pilot只作管线调试，测试集不调参。近重复/正式分词器拟合范围仍待数据工程确定，不能称已经完成。
